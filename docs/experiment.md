# 实验记录 · 自适应 RAG 知识库

> 本文档记录 E0-E5 系列对照实验的固定条件、指标定义与结果。
> E0/E1 在 v1 骨架（30 篇语料 / 171 chunks）上完成，作为历史基线保留；
> E2 起在 v2 代码库（38 篇语料 / 185 chunks，含 8 篇自有排障文档）上重做。

## 一、固定条件

| 项 | 取值 |
|---|---|
| 对话模型 | qwen-plus（百炼 OpenAI 兼容） |
| 向量模型 | text-embedding-v4，1024 维，batch=10（服务商单请求上限） |
| 切块 | RecursiveCharacterTextSplitter，中文分隔符优先（默认 800/120） |
| 检索 | Chroma 向量检索，k=4，按 `kb_id` 权限过滤 |
| 图拓扑 | 路由 → rewrite → retrieve → grade_documents → generate → 质检（三条回退边） |
| 评测集 | `eval/eval_set.jsonl` 30 题：fact 5 / flow 5 / multi 5 / refuse 5 / out 10 |
| 语料 | 腾讯云五大产品文档 30 篇 + 客服规则 5 篇 + 自有排障文档 8 篇 = 38 篇 |

## 二、指标定义

| 指标 | 定义 |
|---|---|
| recall@4 | 可答题中，预期文档出现在 sources 的比例 |
| MRR | 预期文档排名的倒数均值（1.0 = 全部排第一） |
| must_contain | 答案必须包含的关键事实命中率（严格子串 / 归一化去空格两种口径） |
| refuse_acc | 应拒答题中，正确表达"无法确定/转人工"且未泄露禁止内容的比例 |
| cite_rate | 可答题中返回了 sources 的比例 |
| bad_ident | 答案中标识符/状态码在全库找不到的个数（代理校验，非严格 context 校验） |
| P50 / P95 | 端到端延迟 |

**口径说明（重要）**：`must_contain` 原始实现是严格子串比对，答案写「5 GB」而预期关键字是「5GB」会被误判为缺事实。E2 起用 `eval/recheck.py` 做归一化复核（去空格），两种口径同时汇报。

## 三、E0 / E1（v1 历史基线，30 篇语料）

| 指标 | E0 基线 | E1 加双闸 |
|---|---|---|
| recall@4 | 100% | 100% |
| MRR | 1.000 | 1.000 |
| must_contain | 100% | 100% |
| 拒答准确率 | 80% | **100%** |
| 标识符幻觉 | 17 | **2** |
| P50 / P95 | 15.0s / 58.4s | 12.9s / **25.1s** |

E0 的核心发现：检索为空（sources=[]）时仍会调用 generate，模型 3/11 次编造完整开通步骤并**伪造引用**；所有拒答题都跑满 4 轮改写后以空 sources 结束，端到端延迟被拉到 58 秒。

E1 改动（v2 继承）：

- **G1 硬闸**：`generate()` 入口 documents 为空 → 直接返回标准拒答，不调 LLM；
- **G1' 放行**：质检节点识别「已是拒答话术」→ 直接判 useful，避免拒答被判 not useful 后回炉死循环；
- **G2 引用白名单**：解析答案末尾「参考：<X>」，X 归一化后须命中本次 sources；全不中降级拒答，部分不中删掉编造条目。

结果：拒答 80%→100%，幻觉 17→2，P95 58.4→25.1 秒，可答题指标零下降，状态翻转 3 条全部由错转对。

**局限**：评测集题目贴近文档标题，15 条可答题全部 rank=1，recall 100% 被高估——只能证明闸门有效，不能证明检索强。需 E5 补口语化/同义/错别字困难样本。

## 四、E2 切块粒度对比（v2 语料，38 篇）

**实验设计**：同一语料、同一评测集、同一模型参数，只改切块大小，各建一份独立向量库后跑分。800 与 1000 各跑两轮以估计波动（tag 后缀 `-b`）。

| 配置 | chunk_size / overlap | chunks | recall@4 | MRR | must_contain（归一化） | 拒答（两轮） | 幻觉（两轮） | P50 / P95 |
|---|---|---|---|---|---|---|---|---|
| 细粒度 | 500 / 75 | 265 | 100% | 0.967 | 93.3% | 86.7% / — | 14 / — | 10.7s / **59.5s** |
| 生产默认 | 800 / 120 | 184 | 100% | **1.000** | 93.3% | **80.0% / 93.3%** | 13 / 12 | **10.0s** / 34.6s |
| 粗粒度 | 1000 / 150 | 149 | 100% | 0.967 | 93.3% | **86.7% / 86.7%** | **5 / 7** | 10.7s / **33.2s** |

### 结论

1. **切块粒度不是本项目的瓶颈**。三档 recall@4 全部 100%，must_contain 全部 93.3%（同一道 q004 卡住），差异可忽略。语料是结构化产品文档、段落边界清晰，800 上下浮动 200 字不改变语义完整性。
2. **MRR 的 0.967 不是检索退化**。逐条核对：唯一排名非第一的 q004，预期文档仍在 top4 内（rank=2），真正失败原因是 doc_grader 把候选全部判为不相关导致拒答。三档都栽这一题，与切块无关。
3. **细粒度没有换来精度，反而拖慢长尾**。500 产生 265 chunks（800 的 1.44 倍），P95 从 34.6s 涨到 59.5s——块更碎导致 doc_grader 判不相关、触发更多改写重试。
4. **幻觉指标的老实解读**：1000 的 bad_ident 稳定在 5-7，800 稳定在 12-13，差异可复现；但逐条看命中项多为 `console.cloud.tencent.com/cvm`、`Redis`、`Terminal`、`PPT` 这类**通用词与常见 URL**，属代理校验误报。三档共同存在的真实编造只有 q018 一例。所以这条差异说明"粗块给的上下文更完整、模型少用常识填空"，但不能当成"幻觉降了 60%"写进汇报。
5. **拒答指标必须重复跑**。800 两轮 80.0% / 93.3%，1 题之差就是 6.7 个百分点；1000 两轮都是 86.7% 反而稳定。单轮拒答数字不足以支撑结论。
6. **决策：保持生产默认 800/120**。改切块是"动了也没收益"的调参，把精力放到拒答边界上更值。若后续 E5 用更大样本验证出 1000 确实更稳，再考虑切换。

### 定位到的两个真问题（与切块无关，三档/多轮一致复现）

| 题号 | 现象 | 归因 |
|---|---|---|
| q004 | 问「小程序 /cgi-bin/token 的接口调用凭证」，语料里确有该文档，但 top1 被判成《企业微信-获取access_token》，doc_grader 全滤后拒答 | 跨产品同名概念混淆（access_token 两产品都有），检索无产品维度的区分信号 |
| q018 | 问「生命周期规则怎么配置」，语料中「生命周期」仅出现 2 次且为顺带提及，模型却编出完整控制台操作步骤（登录 COS 控制台 → 生命周期 → 创建规则…） | 拒答边界不足：模型用通用产品常识补全了库里没有的操作流程 |

### 局限

- 30 题样本偏小：拒答指标 1 题之差即 6.7 个百分点，800 两轮就出现 80.0%→93.3% 的跳动，说明该指标的置信区间很宽。结论只对"量级"负责，不对"小数点"负责；
- 幻觉指标用「全库」做代理校验，比严格的「本次检索 context」宽松，会同时出现漏报（模型改述的编造）与误报（通用词）；
- 三档配置的 chunk 数差异（265/184/149）只影响检索候选池，k 固定为 4，未做 k 的联合调参；
- `--limit`/单轮跑法未覆盖冷启动抖动，P50/P95 已剔除首题，但仍受网络波动影响。

## 五、E6 拒答边界加固（操作步骤硬约束）

**动机**：E2 发现 q018 —— 问「对象存储生命周期规则怎么配置」，语料里「生命周期」只出现 2 次且为顺带提及，模型却输出"登录 COS 控制台 →【存储桶列表】→【生命周期】→【创建规则】"完整路径。prompt 原有规则 1 已写"资料中没有的路径不得补充"，但被产品常识覆盖。

**改动**（`backend/app/chains.py` 生成提示词新增规则 8）：

> 写任何操作路径前，必须先确认它在【资料】里有对应原文：资料中若只介绍了概念、能力或限制，而没有给出控制台路径、菜单名、按钮名、命令或参数，则只能回答「当前资料未包含具体操作步骤」，并建议通过官方渠道或人工客服获取；严禁按产品常识拼出「登录控制台 → 选择【某菜单】→ 单击【某按钮】」这类流程。判断标准：你写出的每一个菜单/按钮名称，都要能在资料原文中找到同样的字。

**结果**（同一向量库 db_e2_800，两轮）：

| 轮次 | 提示词 | must_contain | 拒答（复算） | 幻觉 | P50 / P95 |
|---|---|---|---|---|---|
| E2-800 | 旧（规则 1-7） | 93.3% | 80.0% / 93.3% | 13 / 12 | 10.0s / 34.6s |
| E2-800-b | 旧 | 93.3% | 93.3% | 12 | 10.4s / 35.0s |
| **E6** | **新（+规则 8）** | 93.3% | **93.3%** | **3** | 10.1s / **19.2s** |
| **E6-b** | **新** | **100.0%** | **93.3%** | **2** | 10.6s / **18.5s** |

### 结论

1. **q018 被真正修好**：模型不再输出控制台路径，改为明确说明「当前资料未包含具体操作步骤」并建议转人工。原始评分器认不出这句新话术（标记词表缺失），复算后拒答 14/15。
2. **幻觉代理计数 13/12 → 2/3，且这次是真降**。逐条核对剩余命中项只剩下 `OpenSSH`、`PuTTY`、`Ctrl` 这类通用技术词，真正的"编造产品路径"已消失。
3. **P95 从 35s 降到 19s，是附带收益**：过去模型给出长步骤 → 幻觉打分判 not supported → 重新生成，白白多跑 1-2 轮 LLM。禁掉编造步骤等于砍掉了重试环。
4. **可答题指标没有下降**：must_contain 93.3%/100%，与加固前持平——说明这条约束没有误伤"资料里确有步骤"的题。
5. **仍有一题越界（q030）**：用户问"你能不能直接帮我重新提交并通过"，模型仍给出"登录公众平台 → 版本管理 → 提交审核"的操作指引。这属于"代为执行"边界，需要另加规则（下一步 E6b），不是本次约束能覆盖的。

## 六、E3 同文档去重与 MMR

**动机**：v1 就发现的「同文档霸榜」——k=4 时 4 个 chunk 常来自同一篇文档，浪费检索位。

**实现**（`RETRIEVER_MODE` 环境变量切换，`backend/app/engine.py` 检索节点）：

| 模式 | 做法 |
|---|---|
| `plain` | 原样 `similarity_search(k=4)` |
| `dedup` | 先取 12 条候选，按 source 去重后每篇只留 1 条，补足 4 条 |
| `mmr` | `max_marginal_relevance_search(k=4, fetch_k=12, λ=0.5)` |

**结果**（全部带 E6 提示词，db_e2_800；归一化口径）：

| 模式 | 轮次 | must_contain | 拒答 | 幻觉 | P50 / P95 |
|---|---|---|---|---|---|
| plain | E6 / E6-b | 93.3% / 100% | 93.3% / 93.3% | 3 / 2 | 10.1s / 19.2s |
| **dedup** | 两轮 | 93.3% / 93.3% | 93.3% / 93.3% | **2 / 2** | 10.1s / **15.1s** |
| mmr | 一轮 | 93.3% | 93.3% | 6 | 10.5s / 17.2s |

### 结论

1. **三档在质量指标上打平，MMR 反而更差**（幻觉 6 > 2/3）。MMR 用多样性换相关性，在"答案集中在同一篇文档"的产品文档场景里是减分：把相关 chunk 换成了不相关的其它文档。
2. **dedup 有小幅但一致的优势**：两轮幻觉都是 2，P95 15.1/16.2s，比 plain 的 19.2/18.5s 稳定快 3 秒左右。原因是候选文档不重复 → 幻觉打分与答案打分更容易一次通过，少一轮重试。
3. **但这套评测集体现不出检索改进**：15 条可答题的预期文档在三种模式下都排第一（MRR=1.0），天花板效应明显。dedup 的真实价值要等 E5 困难样本才能验证。
4. **决策：把 `dedup` 设为默认**（`RETRIEVER_MODE` 可随时回退 plain）。零新增依赖、代码不到 20 行、有稳定的小幅收益。
