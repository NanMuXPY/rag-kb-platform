## 零、七条裁定（先看这个，理由在后文）

| # | 问题 | 裁定 | 一句话理由 |
|---|---|---|---|
| 1 | 门户是第 4 个页签吗 | **不是。门户 = 「问答」页签的 idle 态** | 它没有独立的模块语义，只是问答在"还没有会话"时的样子；变成第 4 个页签等于把"入口"伪装成"模块" |
| 2 | composer 还留吗 | **留，常驻底部** | 门户的用途是"先概览再对话"，把输入框拿走就只剩概览 |
| 3 | 「＋ 新会话」按钮 | **删除**（`#btnNew` 从 rail 移除） | 点「问答」页签 = 回门户 = 新会话，两个入口指向同一结果，正是"感觉没必要"的来源 |
| 4 | 版心 | **`--content-work` 1200px**（不新增） | 三列卡片在 880 阅读版心里每列只有 274px，装不下"库名+分级戳+状态徽标" |
| 5 | 卡片列数 | **`repeat(auto-fit, minmax(300px, 1fr))`** | 列数由容器自己算，不写死 3 列 —— 只有 1 个库时卡片铺满整行，而不是 1/3 宽留两个空洞 |
| 6 | 「最近更新」放哪 | **段 1 内部、卡片行下方一条 24px 单行条**，不单独成块 | 它是"刚刚什么变了"的一次性信号；给它段头就会读成第 2 个区块。代价是首屏 +32px → 余量归 0（team-lead 裁定，降级阀见 §2.2） |
| 7 | 段落分隔 | **24px 留白，0 条分隔线，0 张外框卡片组** | 本系统靠 `--line` 一条线分界；四段内容再包四层框就变成"卡片里放卡片" |

## 一、定位与页头归属

### 1.1 为什么不是第 4 个页签

现有 `.view-nav` 是「换模块」的锚点（问答 / 知识库 / 控制台），用户靠它回答"我在哪个系统里"。门户回答的是"问答模块里有没有正在进行的会话"，是**同一模块的两种态**，不是第二个模块：

1. **语义**：门户上的每个可点元素（知识库卡、常用问题、最近提问）最终都打开**同一条问答流**。页签应该是并列目的地的集合，而门户的每个出口都通向"问答"本身。
2. **位置预算**：`≤720` 时 `.topbar` 已经 `flex-wrap: wrap`（`app.css:566`），三个页签 + 汉堡 + 标题已接近一行上限。第 4 个页签会把 `scope-note` 挤到第二行，换来一个语义重复的按钮。
3. **判定成本**：用户第一次进来要分辨「问答」和「门户」有什么区别 —— 而正确答案是"没区别"。一个需要解释的页签就是错的页签。

### 1.2 状态机：门户是 `#viewChat` 的 idle

| 状态 | 触发 | 页面内容 | URL |
|---|---|---|---|
| `idle`（门户） | 登录后首次进入 / 点「问答」页签 / 从 `thread` 点「问答」页签 | 门户四段 + composer | `#chat` |
| `thread`（对话） | 发出一条消息 / 点常用问题 / 点 rail 或最近提问里的任一条会话 | `.messages` + composer，门户四段整体卸载 | `#chat/s/<id>` |
| 回退 | 点「问答」页签 / 浏览器后退 | 回到 `idle`，门户按最新数据重渲染 | `#chat` |

> **路由口径以本节为准（team-lead 裁定，v1.1）**：**不新增 `#home`**，idle 态就是 `#chat`，会话态是 `#chat/s/<id>`（会话 id 进路径，与 `#kb/{id}/{section}` 同一套解析）。理由有两条：① 新增 `#home` 要动 `parseHash/applyRoute/showView` 三处守卫与 `#viewNav` 的高亮映射，等于给一个"页签语义没变"的改动付出新增视图的成本；② 会话 id 放 query（`#chat?s=`）会和现有"筛选进 URL"的写法混在一起，路径段更省心。

**同容器替换，不跳页**：门户与消息流共用 `#thread` 这一个滚动容器。发出第一条消息时，`.portal` 直接 `hidden`，`.messages` 展开 —— 视口不闪、滚动位置归零、composer 位置不动（`--bar-h` 那套"等高替换"的同一思路，见后台 §5.4）。**禁止做页面级转场动画**（上位原则 4：动效只交代因果，这里没有"从哪来"）。

### 1.3 「＋ 新会话」的处置

删除 `#btnNew`，替代路径写进文档：

- rail 顶部只留品牌区（`brand-name` / `brand-sub`），高度从 18+14 收到 `--sp-4` 16px 下边距。
- "新会话"的操作 = 点「问答」页签（任何视图下都常驻可见），或从 `thread` 态点 rail 里任意一个**已存在的会话**。
- **不改成「回到门户」文字按钮**：那是把同一个语义换个名字留在原地，用户仍会问"它和问答页签什么关系"。

### 2.2 纵向预算（1440 × 900 首屏必须装下四段）

| 区 | 高 | 拆解（令牌 / px） |

| `view-pad` 上内边距 | 22 | 既有 `.view-pad`（`app.css:881`，锚点 `.view-pad`），不改 |
| 页头 | **73** | 标题行 27（`--fs-xl` × `--lh-tight` 27）+ 4（`--sp-1`）+ 副行 18 + 下边距 24（`--sp-6`） |
| 段 1 · 知识库（**含更新条**） | **140** | 段头 22 + 12（`--sp-3`）+ 卡片行 74 + **更新条 32**（上间距 8 + 条高 24） |

### 2.3 容器与网格

```css
/* 两层：外层撑满主区并吃掉内边距，内层才是 1136 的版心 */
.portal { padding: 22px 28px 40px; }      /* 顶替 .view-pad，数值不变 */
.portal-inner {
  max-width: var(--content-work);         /* 1200 → 实得 1136 */
  margin: 0 auto;
  container-type: inline-size;
  container-name: portal;                 /* 必须命名，见下 */
}
.portal-cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));
  gap: var(--sp-3);                       /* 12px */
}
```

- **`container-type` 必须挂 `.portal-inner`，不能挂 `.portal`**：`@container` 量的是最近的容器祖先宽度。挂外层量到的是主区 **1192**（1440 − 248），挂内层才是版心 **1136** —— 差 56px 会让 924 / 612 两条阈值整体偏一档（1440 上看不出来，1000 时提前折行）。
- **`container-name: portal` 不能省**：详情区、页签区将来都可能建容器，不命名会命中"最近的那个"而不是你以为的那个，且**静默失效**（不报错、只是不生效）。

- **列数不写死**。`auto-fit` 会把空轨道并掉：1 张卡 = 占满整行 1136，2 张 = 各 562，3 张以上 = 3 列 370.67。这正是"新员工只有 1 个库"时页面不显得崩掉的机制（见 §5）。
- `300px` 是内容下限，不是审美值：卡内主行 = 库名（≥8 汉字 112px）+ 分级戳 40 + 状态徽标 62 + 2 × 8px 间隙 = 230，加左右各 16 padding = **262**；取 300 留 38px 给超长库名截断。
- 为什么不是 `minmax(280px)`：`1136 / 280 = 4.05` 会挤出 **4 列**，每列 274 —— 卡内主行装不下状态徽标，库名被压到 4 字。

## 三、四段逐块规格

### 3.1 页头

| 元素 | 令牌 / 值 | 理由 |
|---|---|---|
| 问候语 | `--serif` `--fs-xl` 20px / 700 / `--lh-tight` / `--ink` | 与 `.work-title` 同级同规格（后台 §2.4）：门户是"第一屏标题"，不该比列表页标题弱 |
| 文案 | 「下午好，李工」/「早上好」按 12:00 切，无姓名时回退「你好」 | 不写"欢迎使用"——那是官网语汇 |
| 副行 | `--fs-xs` 12px / 400 / `--muted`，`margin-top: var(--sp-1)` | 承载"你的权限范围"这个事实，替代"共 4 个库"这种重复计数 |
| 副行文案 | 「你有 N 个知识库的访问权限 · 上次提问 3 天前」 | N 由 `GET /kbs` 返回条数直接得（不是另调接口）；无历史时后半句省略，不留 `·` |
| 右侧动作 | 文字 12px / 600 / `--blue`，热区 28px（`::after` 扩），仅管理员渲染 | 页头硬上限 3 个控件（后台 §2.4），这里只用 1 个 |
| 页头下边距 | 24（`--sp-6`） | 段间距同值，页头与段 1 的关系 = 段与段的关系 |

**为什么页头不放大标题 + 副标题两行结构（`work-head` 那套）**：`work-head` 是"页面名 + 对象总数 + 主操作"，用于列表页。门户没有"对象总数"这个概念（四段内容量纲不同），硬套会出现"门户 4 个"这种没有意义的副标题。

### 3.2 段头（三个带标题的段共用一个规格）

```
我有权限的知识库                                    全部 4 个 ›
```

| 元素 | 规格 |
|---|---|
| 标题 | `--fs-lg` 16px / 700 / `--serif` / `--ink`，`line-height: 1.35`（21.6 ≈ 22） |
| 计数 / 补充 | `--fs-xs` 12px / 400 / `--muted`，距标题 `--sp-2`，基线对齐 |
| 右侧文字动作 | `--fs-xs` 12px / 600 / `--blue`，热区 28px 高；**不是按钮**（沿用 `hint-bar` 动作规格，后台 §5.2） |
| 段头下间距 | 12（`--sp-3`） |
| 装饰 | **无竖条、无下划线、无图标** |

> 段标题用衬线 16px，是为了和卡片名（14px sans 600）拉开一个层级。若都用 14/600，段标题与卡名同重，段与段的分界会消失。

**不用 `.admin-sec h3` 的 3px 朱砂竖条**：那是控制台"操作区"的语汇。门户属于阅读器一侧（问答域），三个段头各挂一条朱砂，会读出"三个都要处理"，与"概览"矛盾。

### 3.3 知识库卡

```
┌──────────────────────────────────────────┐
│ 财务制度库            [内部]   ● 启用     │  20px：名 14/600 · 戳 20 · 状态 20
│ KB-FIN-001 · 财务部 · 只读    128 更新 3 天前│  16px：mono 11 · 部门 · 角色 · 计数 + 时间
└──────────────────────────────────────────┘   74px（padding 16 / 16）
```

| 元素 | 令牌 / 值 | 理由 |
|---|---|---|
| 卡容器 | 底 `--surface`，边 `1px --line`，`--r-md` 8px，**`box-shadow: none`** | 上位原则 3：边界靠线。三张卡各带阴影 = 三个浮块，和档案风冲突 |
| 卡内边距 | 16 / 16（`--sp-4`） | 行高 20 + 6 + 16 = 42，+32 = 74 |
| 卡高 | 74（由内容决定，不写 `height`） | 1 张卡铺满整行时（1136 × 74）读起来像一条列表行，不像被拉扁的卡片 |
| 库名 | `--fs-base` 14px / 600 / `--ink`，单行截断 + `title` | 与后台表格主字段 13/600 差一号：卡片不是表格，可以大一档 |
| 分级戳 | `.cls` 20px 线框（后台 §4.2），`--fs-xs` | 维度 1 = 线框（形态即维度） |
| 状态徽标 | `.st` 实底 + 5px 圆点（后台 §4.3），20px | 维度 2 = 实底。**一张卡最多 1 个实底 + 1 个线框**（后台 §4.5 色彩预算） |
| 编码 | `--mono` `--fs-2xs` 11px / `--muted` | 后台 §3.2 编码列同字体，跨页认知一致 |
| 部门 | `--fs-xs` 12px / `--muted`，与编码之间 ` · ` | 分隔符用 `·` 不用 `|`：`|` 在纸感里像表格竖线 |
| 我的角色 | `--fs-2xs` 11px / 500 / `--ink-soft`，**纯文字**（`只读 / 可上传 / 库管理员 / 超管`），复用 `ROLE_CN` | 第三个维度只能给文字：分级已占线框、状态已占实底，角色再做徽标就是一行 3 个色块（后台 §4.5 超预算） |
| 文件数 | `--mono` 12px，**右对齐**，`tabular-nums`；0 显示 `—`（`--muted`）；默认库（`id === 1`）显示 `内置语料` | 后台 §3.8 计数右对齐；默认库文件区恒空是设计事实，写 `0 个文件` 会被读成"库是空的" |
| 时间 | `--mono` 12px / `--muted`，右对齐，宽 88 | ≤7 天相对时间，>7 天 `2026-10-21`（后台 §3.8） |
| 行内右组 | 文件数 + 时间，`gap: var(--sp-3)`，`margin-left: auto` | 与左组（编码 · 部门 · 角色）形成"左读右数"的动线 |

**时间标签写「更新」，不写「变更」**（这一条**推翻**后台 §3.5 的旧口径，理由在代码里）：
后台 §3.5 当年写「`updated_at` 只在 `PATCH` 时 bump、上传文件不更新，所以列名叫变更时间且不可排序」。**现状已不成立** —— `workspace.touch_kb()` 的 docstring 明确写着"文件增删审批都算维护动作"，调用点有 4 处：上传（`main.py:470`）、审批（502）、驳回（514）、删除文件（528）。所以 `updated_at` 现在是**真正的"最后更新"**，门户写「更新 3 天前」是准确的。

- 标签文字：`更新`；`title="最近一次配置变更或文件变动"`。
- **连带结论**：后台 §3.5 的「变更时间」列名与「不可排序」两条需要回收（本文不改那份文件，留给维护者按后台 §9 的"结论变更须三方通知"处理）。在回收之前，**门户以本节为准**，不要跟着旧口径把标签改成「变更」。

**卡片顺序**（team-lead 裁定）：`my_role` 权重降序（super 4 > kb_admin 3 > editor 2 > viewer 1）→ `updated_at` 降序 → `id` 升序（稳定）。理由：门户回答"我要去哪里**做事**"，能管理的库必须排前面。**不提供排序控件**（门户不是列表页，加排序就要连带动箭头、空态、"恢复默认"）。

> **代价必须记下来**：按角色排序后，"哪个库刚被动过"在卡片顺序里看不出来了 —— 这正是段 1 内那条 24px「最近更新」条存在的唯一理由。两者是一组，**不许只留一个**。

**截断为 3 张**（UX 已同步为 ≤3，见 `门户首页交互.md` §5.2）：6 张 = 2 行卡片 = 段 1 高 182（+74），页总高变 777 > 747，**「常用问题」被推出首屏** —— 而常用问题正是新员工的无历史兜底路径，比"第 4–6 个库"重要。

> 若坚持 6 张，代价是明确的：砍掉「最近更新」条（−32，仍差 42）或把「最近提问」压到 1 行 —— 两者都比"少看三个库"更伤。**不允许靠压内边距凑。**

### 3.4 最近更新（单行条）

```
最近更新   财务制度库 · 2 小时前    产品通用知识库 · 昨天 · 12 个文件    全部 ›
```

| 元素 | 令牌 / 值 | 理由 |
|---|---|---|
| 形态 | **单行 24px 高**，无外框、无底色、无段头，**长在段 1 内部**（卡片行下方 8px） | 它是段 1 的脚注而不是第 2 个区块：一有段头就会与「最近提问」「常用问题」并列成三块，页面读起来变四块内容 |
| 上间距 | 8（`--sp-2`） | 与卡片行贴得近，表达"这是上面那排卡的补充" |
| 标签 | 「最近更新」`--fs-xs` 12px / 600 / `--ink-soft` | 用一个词交代这行是什么；不加图标 |
| 条目 | 最多 2 条，每条 `库名 · 相对时间 [· N 个文件]`：库名 12px / 500 / `--ink`，其余 12px / 400 / `--muted` | 2 条是硬上限：1136 宽下 2 条各约 380px，第 3 条开始会挤掉右侧动作 |
| 条目间隔 | `--sp-8` 32px | 比 `--sp-6` 大一档：它们是并列的独立事实，不是一句话的分句 |
| 右侧动作 | 「全部 ›」`--fs-xs` 12px / 600 / `--blue`，热区 28px | 跳 `#kb`（按更新时间排序的那一屏） |
| 排序 | `updated_at` 降序，取前 2 | 与卡片同源同序，不会出现"卡片第 1 张 ≠ 条里第 1 个" |
| 默认库 | 显示 `内置语料` 代替文件数 | 同卡片，理由见 §3.3 |

**为什么它与卡片不重复**（这是唯一一条需要论证的重复风险）：
卡片回答"**我能进哪些库**"（全量、按更新排、可点进文件区）；这条回答"**刚刚有什么变了**"（只 2 条、强调时间与文件数、点进同一个详情）。两处都要画，是因为用户在门户上有两个不同的问题；但**数据必须同源同序**，否则就是两个真相。

**禁止**：把它做成第二条卡片行（那就是 6 张卡的另一种写法，首屏预算 777 直接爆）；也不要给它加"新"字红点 —— 朱砂在本系统里是"不可外流/出错/品牌"，不是"有新内容"。

### 3.5 最近提问

一行 44px，五段（字段集与 `门户首页交互.md` §4.3 对齐，不多不少）：

| 段 | 宽 | 内容 | 令牌 |
|---|---|---|---|
| 问题 | `1fr`，`min-width: 0` | 单行截断 + `title`（≤120 字） | `--fs-sm` 13px / 400 / `--ink` |
| 轮次 | 48，右对齐 | `· 3 轮`，仅 `msgs.length > 2` 时渲染 | `--fs-xs` 12px / `--muted` |
| 来源库 | 120，单行截断 | 该会话最后一条 assistant 消息的 `sources[0].kb_id` → `kbLabel()` | `--fs-xs` 12px / `--muted` |
| 时间 | 84，**右对齐** | `tsInfo(m.ts)`；旧数据无 `ts` 显示「较早」 | `--mono` `--fs-xs` / `--muted` |
| 箭头 | 12 | `›` | `--line-strong`，hover 时 `--blue` |

> **四段之间有 `--sp-3` 12px 间隙，总固定宽 = 48+120+84+12 + 3×12 = 300**，1136 容器下问题段得 **812**；362 容器下（390，整段已折叠进 `<details>`）展开时**隐藏「来源库」与「轮次」**，问题段得 218（338 − 84 时间 − 12 箭头 − 2×12 间隙），只留时间。
>
> **来源库为空时整段不渲染**（不是写 `—`）：它是从引用片段读出来的，读不到就是没有，用 `—` 会变成"数据缺失"。这条与后台 §3.8 的 `—` 规则不冲突 —— `—` 表示"有这个字段但没读到"，这里表示"没有这个字段"。

| 规格 | 值 |
|---|---|
| 行高 | 44（比表格 48 矮：门户一行一款，不做双行） |
| 行间线 | `1px --line`，最后一行不画 |
| hover 底 | `--paper`（= `--row-hover`，后台 §3.6："暖一档纸色，不用灰"） |
| 上限 | 4 行；第 5 条起进段头动作「会话 ›」 |
| 数据源 | `localStorage` 的会话记录（同一份数据，**不新调接口**）；去重与排序按 UX §4.2（归一化空白去重、`ts` 倒序、会话置顶） |

**点击行为必须是"恢复会话"，不是"重问"**：点第 2 行 → 进 `thread` 态、滚到该轮、composer 带上该轮的会话上下文。若做成"重新发送"，同一个问题会被重复问一次、多花一次 LLM 费用 —— 且用户在 rail 里点同一项得到的结果不同，这就是"两个入口两种行为"。

### 3.6 常用问题

```
· 对象存储怎么创建存储桶？
· 企业微信如何获取 access_token？
```

| 元素 | 规格 |
|---|---|
| 行高 | 36px（比"最近提问"更矮：这是句子列表，不是记录列表） |
| 行首字符 | `·`（U+00B7），`--line-strong`，与文字间距 4px（`--sp-icon` 的 4px 对齐写法，用 `--sp-1`） |
| 文字 | `--fs-sm` 13px / 400 / `--ink`，单行，**不截断**（超过容器时整行换行，行高自动增高） |
| hover | 文字 `--blue` + `text-decoration: underline`，`text-underline-offset: 3px`；`·` 保持 `--line-strong` |
| 点击 | 直接把该句**原文**写入 composer 并发送（等价于用户手打），随后进 `thread` 态 |
| 数量 | 5 条，与 `#samples` 的 5 条**同一份数据源** |

**为什么不是胶囊按钮**：现有 `.sample` 是 `--r-full` 胶囊。5 个胶囊在 1200 版心里横排会换行成 3+2，每行高度不一，视觉上像"标签云"。改成句子列表后，五行左对齐、基线一致，读起来是"目录"而不是"筛选项"。**形态差异也承担语义**：胶囊 = 可切换的筛选/标签（`.ufilter` 已占用），句子 = 可执行的一问。

**为什么不要图标/编号**：`·` 已经是全系统"轻提示"的字符（`hint-bar` 行首同款）。加 `1.2.3.` 会让它看起来像有序步骤，加 `›` 会和"最近提问"的箭头符号撞车。

## 五、空态：1 个库 + 0 条提问

这是**唯一真实可达的"少数据"场景**（`GET /kbs` 恒含默认库，`rows === 0` 不可达，后台 §5.2）。目标是"页面不显得像崩了"，办法是**让空的那一段变矮，而不是变空**：

| 段 | 常态 | 1 库 + 0 提问时 | 高度变化 |
|---|---|---|---|
| 页头 | 「你有 4 个知识库…」 | 「你有 1 个知识库的访问权限」，**后半句整句省略**（不留孤立 `·`） | 0 |
| 段 1 | 3 张卡 + 更新条 | **1 张卡铺满整行 1136**（`auto-fit` 自动并轨）；更新条**仍显示**（与提问无关，只看 `GET /kbs`） | 0 |
| 段 2 | 4 行（176） | `hint-bar` 32px：`· 还没有提问记录 · 从下面挑一个问题开始` | −144 |
| 段 3 | 5 行（180） | 不变，段头文案由「常用问题」改为「可以从这些问题开始」 | 0 |
| 页总高 | **747** | **603** | −144 |

三条硬规则：

1. **不许出现高度 > 40px 的空白容器**。空的那一段要么是 `hint-bar`（32px），要么整段不渲染 —— 但段 2 必须渲染，因为它是"你可以从这里开始"的引导位。
2. **段 2 的 `hint-bar` 不是空态**。它没有 64px 上下留白、没有 36px 字符图形、没有主按钮（后台 §5.2 的三种空态里，这里属于"只有默认库"那一类的轻提示）。动作是句末文字，不是按钮。
3. **不显示"0"**：计数为 0 的地方一律 `—`（后台 §3.8），例如 1 个库且库内 0 文件时的文件数。一段"0 · 0 · 0"会让页面读起来像出错。

> 只有 1 个库时，段头右侧**不出现**「全部 1 个 ›」—— 动作指向的页面里只有它自己，等于给了一个空跳转。判定：`count > 3` 才渲染该动作（与"只渲染前 3 张"同一条阈值，避免出现"全部 1 个"与"1 张卡"并存的矛盾）。

## 六、权限差异

| 元素 | 员工（viewer / editor / kb_admin） | 管理员（admin） |
|---|---|---|
| 页头右上动作 | **节点不渲染** | 渲染「控制台 ›」（12/600 `--blue`，28px 热区）→ `#admin` |
| 知识库卡 | 只含 `my_role` 非空的库（后端已过滤） | 多出"全部库"的可见量，但**卡片版式完全相同** |
| 段 1 段头动作 | 「全部 N 个 ›」 | 同左（**不加**「＋ 新建知识库」—— 建库属于 `#kb` 列表页的页头主操作，后台 §2.4） |
| 段 2 | 只有自己的会话 | 同左（**管理员看不到别人的会话**，门户不是审计工具） |
| 待审批提醒 | 无 | **门户不放**「待审批 N」徽标 —— 那是控制台的职责，放两处必然出现两个数字不一致 |

两条判定依据：

- **管理员的额外入口只加 1 个，且是文字动作不是按钮**。门户的第一屏要回答"我要查什么"，不是"我要管什么"。给管理员加一排管理按钮，等于把控制台搬到首页。
- **同一张卡不做两种排版**。按角色改卡片结构（例如给管理员加"成员数"）会让截图对账失效、让"去色自检"失效（多一列数字，层级就靠颜色硬撑了）。

## 七、响应式三档

列数由 `auto-fit` 决定，**不写任何视口断点**；只在需要改"条数"和"折叠"时用容器查询（`@container`，后台 §3.3 已有先例：容器查询不算新增断点）。

| 视口 | rail | 容器宽（1136 基准 = 视口 − rail 248 − 左右 28×2） | 卡片列数 | 卡宽 | 最近提问 | 常用问题 |
|---|---|---|---|---|---|---|
| **1440** | 展开 248 | **1136** | **3** | 370.67 | 4 行 | 5 条 |
| **1280** | 展开 248 | 976 | 3 | 317.33 | 4 行 | 5 条 |
| **1180** | 展开 248 | 876 | **2** | 432 | 4 行 | 5 条 |
| **1000** | 展开 248 | **696** | **2** | **342** | 3 行 | 5 条 |
| 860 | 浮层抽屉（`≤860` 既有规则） | 804 | 2 | 396 | 4 行 | 5 条 |
| 720 | 浮层抽屉，`view-pad` 收到 14 | 692 | 2 | 340 | 3 行 | 5 条 |
| **390** | 浮层抽屉，padding 14 | **362** | **1** | **362** | **整段折叠**（`<details>`） | 5 条 |

**列数阈值只有两条，且都由 300 / 12 算出**（767 / 611 / 419 那三条是内容阈值，见下）：

- 3 列需容器 ≥ `3×300 + 2×12` = **924**
- 2 列需容器 ≥ `2×300 + 1×12` = **612**

**只有提问行数需要写 `@container`**：卡片列数由 `auto-fit + minmax(300px)` 自动完成，写进 CSS 反而会和它打架。完整写法只存在一份，见本节末「折叠顺序」下的代码块 —— 那里也写明了 `< 420` 为什么不靠 CSS（要换语义成 `<details>`）。

阈值取 **767 / 611** 而不是 768 / 612：`max-width: 924px` 会**包含** 924 本身，而 924 恰好还能放 3 列 —— 差 1px 就是在最挤的那一档多折一行。所以「≥924 三列」对应的查询上界是 **923**，2 列的下界 612 对应上界 **611**。

**1000 档为什么是 2 列 342 而不是 3 列 306**：门户**不参与** `innerWidth < 1180` 的 rail 自动折叠（那条规则是给 `#kb` / `#admin` 的，后台 §3.3）。门户属于问答域，左侧会话列表是"回访上一轮"的入口，收掉它换来的 248px 不足以弥补"找不到上次的会话"。因此 1000 时容器 = 1000 − 248 − 56 = 696 → 2 列。

> **这是一条容易做错的地方**：如果前端把 rail-collapsed 的判定从"kb/admin 视图"扩到"所有视图"，1000 会变成 3 列 306px，卡内主行装不下状态徽标（230 + 32 = 262 < 306，勉强；但库名只剩 8 字），且打开 `#kb` 再回 `#chat` 时 rail 会跳一次。规范要求：**折叠判定必须按视图白名单（kb / admin），不用黑名单。**

### 折叠顺序（内容不够放时先砍谁）

| 顺位 | 何时砍 | 砍什么 | 为什么是它 |
|---|---|---|---|
| 1 | 容器 ≤ **923** | 卡片 3 → 2 列（`auto-fit` 自动，无需查询） | 版式问题优先用版式解决，不动内容 |
| 2 | 容器 ≤ **767** | 最近提问 4 → 3 行 | 它是**回顾**，不是**入口**；少一行不影响"下一步做什么" |
| 3 | 容器 ≤ **611** | 卡片 2 → 1 列（自动）；最近提问 3 → 2 行 | 仍先砍回顾；更新条**不砍**（它是唯一的变化信号） |
| 4 | 容器 ≤ **419** | 最近提问整段收进 `<details>`（标题「最近提问（2）」，默认收起）；更新条保留 1 条 | 390 时四段纵向已 500+px，回顾的价值低于"常用问题" |
| — | **永不砍** | 常用问题 5 条 | 它是这个页面存在的理由（用户原话："点问题或知识库才进对话"） |

`@container` 写法（阈值与上表同源，只允许存在一份）：

```css
/* 卡片 3→2→1 列：不写规则，auto-fit + minmax(300px) 自动完成（阈值 924 / 612 由算式推出） */
@container portal (max-width: 767px) { .recent-row:nth-child(n+4) { display: none; } }
@container portal (max-width: 611px) { .recent-row:nth-child(n+3) { display: none; } }
/* < 420：JS 把 .portal-recent 渲染成 <details>（无 open），不靠 CSS 造折叠 */
```
