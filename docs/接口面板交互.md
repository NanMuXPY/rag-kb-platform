# 接口面板交互 · `#admin/api`

> 版本 **v1.2**（2026-11-03）｜ 适用：控制台第 5 个页签「接口」
> 上位文档：`docs/后台交互规范.md`（v1.13，下称"交互规范"）+ `docs/后台视觉规范.md`（v1.14，下称"视觉规范"）
> **平行文档**：`docs/接口面板设计.md`（v1.1，下称"设计文"，负责骨架/尺寸/令牌/配色）。**分工**：凡是"长什么样、多宽、什么颜色"以设计文为准，本文不复述；凡"点了发生什么、请求发几次、失败了怎么办、能不能发"以本文为准。两份文档的差异与对账见 §15。
>
> **v1.1 变更（与设计文 v1.1 对齐）**：① `/open/v1/*` 的定性由 `forbidden` 改为 **`locked`**（钥匙在服务端可配置，不是谁都拿不到的权利），结论仍是"画 + 锁 + 说明钥匙在哪"（§5.3 / §15.2 第 2 行）；② 修正"6 组"笔误为 7 组（附录 A）；③ 非管理员兜底落点由 `#home` 改为 **`#chat`（门户）**（§12 / §14 验收）。
>
> **v1.2 变更（后端 v2.2 上了 `gate_schema`，事实变了，不是行号误差）**：① 契约 `GET /api/openapi.json` **现在要求登录**（未登录 401），§2.1 请求头改为必须带 JWT；② **失败**态由四类扩为五类（整体状态仍是四态，§12），401 与 403 分开：401 → 整页 `登录已过期` + **只给「重新登录」、不给「重试」**；403 → `当前账号无权查看接口清单`，**两个按钮都不给**（重登无效、重试也无效）（§2.2）；③ 删掉 v1.1 的"执行层锁、非展示层遮"这句话 —— 展示层现在也锁了（§15.4 重写为"已由后端闭合"）；④ F2 从"默认参数、无 `docs_url=None`"改为"已关自带文档 + 中间件拦三条路径"。
>
> **行号基准（v1.2 已更新现值）**：`app.js` **4787** / `app.css` **2417** / `main.py` **774** / `security.py` 位于 `backend/app/`（不是 `backend/api/`）。每条引用都带**锚点**（函数名 / 路由名 / 选择器），复核按锚点走，不要只看行号 —— v2.2 加中间件时 `main.py` 后半段整体下移过。
>
> **定位**：给**人**和**AI**看同一份接口真相（服务端自动生成的契约，不是手抄文档），并允许**在线试调用**核对"它到底返回什么"。
> 它替代的是"翻源码 / 猜参数 / 用 curl 试三次"的过程，不是替代 Swagger。
>
> **一页话结论**：左侧按前缀分组列出**全部 46 个操作**（不是 60+，见 §0 F1）；右侧是"参数 → 发送 → 原始响应"；**能发的不多**——流式、二进制、multipart、API-Key 四类**禁用**；所有非 GET 操作至少 2 级确认；**4 个不可恢复的 `DELETE` 输 `DELETE` 才放行**，另 2 个可一次反向请求还原的降到 2/3 级（§6.2）—— 方法名不等于不可逆。

## 一、定位与页签位置

### 1.1 页签顺序：**排第 5，稳定在最后**（名字叫「接口」，不叫「API 文档」）

```
语料索引 → 用户管理 → 权限矩阵 → 审计日志 → 接口
   1          2          3          4          5
```

**理由三条**：

1. **不拆散 2→3 的相邻关系**。交互规范 §1.2 明文规定「设分组是矩阵的前置动作」，用户管理必须紧邻权限矩阵。把接口面板插进去，是为一个低频排障页破坏一条高频路径。
2. **按频率排**：前四个是日常治理，接口面板是"出问题时才来"。放末尾符合"越往后越少用"的序。
3. **不是"越权"**：它只对管理员可见（`applyRoute` 的 admin 守卫），是控制台内部的第 5 个视图，不是第 4 个一级模块。

### 1.2 hash

| hash | 渲染 | 说明 |
|---|---|---|
| `#admin/api` | 面板（左侧默认选中第一个分组的第一条） | 模块入口 |
| `#admin/api?ep=GET:/kbs` | 选中该操作 | `encodeURIComponent("GET:/kbs")`；**不放路径段**，因为路径本身带 `/`，塞进路径段要二次编码，读起来是 `%2F` 地狱 |
| `#admin/api?ep=POST:/chat&q=审计` | 选中 + 左侧筛选词 | `q` 用 `replaceState`（同交互规范 §2.2 搜索词规则） |
| `#admin/api?ep=DELETE:/kbs/1` | 选中 + 参数预填 `kb_id=1` | 参数值可放 URL 时**只放 path 参数**（短、无敏感信息）；**query/body 一律不进 URL**（可能含密码，见 §10） |

**为什么选中的接口要进 URL**：管理员之间最常见的对话是"你看下 `DELETE /kbs/1` 这个返回"，一条可粘贴的链接比"第 4 组第 12 个"准确。

## 二、取数：`GET /api/openapi.json`

### 2.1 请求与缓存

| 项 | 规格 |
|---|---|
| URL | `API_BASE + "/openapi.json"`（复用 `app.js:12` 的 `API_BASE`：nginx 下是 `/api`，本地直连是 `http://127.0.0.1:14052`） |
| 请求头 | **必须带 `Authorization`**（`authHeaders(false)`，`app.js:37`）。后端 v2.2 起 `gate_schema` 中间件（`main.py:38-49`）对 `/openapi.json`、`/docs`、`/redoc` 三条路径统一走 `get_current_user`，**未登录 401**。这不是"契约要登录"，是"契约不给没登录的人看" —— 见 §15.4 的定性 |
| 缓存 | 内存 5 分钟（`{doc, at}`）；进入页签时 `Date.now() - at > 5min` 才重拉 |
| 刷新 | 标题行右侧「刷新契约」文字按钮；点击强制重拉并保留当前选中（按 `method+path` 匹配，匹配不到则回第一条） |
| 并发 | 复用 in-flight Promise，快速来回切页签只发 1 次 |
| 超时 | 10s（`AbortController`），比普通试调用短：静态文档不该等 |

### 2.2 失败五态与降级文案（**不许空白页**）

| 情况 | 判定 | 界面 |
|---|---|---|
| 网络不可达 | `fetch` throw | `接口文档加载失败` / `无法连接后端（{API_BASE}）。请确认服务已启动，或检查网络。` + 「重试」 |
| **401（登录已过期）** | `r.status === 401` | 整页 `登录已过期` + **只给「重新登录」**（点它 = `showAuth()`）。**不给「重试」**：同一个过期 token 重试多少次都是 401，给重试等于让用户点着玩；也不写"接口文档加载失败"，否则用户会以为面板坏了，而不是登录掉了 |
| 403 | `r.status === 403` | `当前账号无权查看接口清单`（设计文 v1.2 §5.3 同句）。**不给「重新登录」**（身份不够 ≠ 身份没了，重登无效）、**也不给「重试」**（同一次请求再发仍是 403），只留一句指向：「请联系系统管理员」 |
| 非 JSON（**最隐蔽的一种**） | `content-type` 不含 `json`，或 `r.json()` throw | `返回的不是 JSON` / `反代可能把 /api/openapi.json 交给了前端页面（返回了 HTML）。检查 nginx 的 location /api/ 配置。` + 「重试」 |
| JSON 但无 `paths` | `!doc.paths \|\| !Object.keys(doc.paths).length` | `契约文件是空的` / `openapi.json 里没有 paths，后端可能一个路由都没注册。` |

**"非 JSON"必须单独做**：nginx 的 `try_files $uri $uri/ /index.html` 会把任何未命中路径回成 **200 + HTML**。如果只判 `r.ok`，面板会显示一个空白列表，且状态码是 200 —— 那是最难查的一类故障。文案里直接点名 nginx，是因为**这就是它最可能的成因**。

**401 与 403 必须分开做**（v1.1 新增，v1.2 补第三段）：401 = "票过期了，换一张"（用户自己能自愈 → 给按钮）；403 = "票不够格"（重登无效、重试也无效 → 只给说明，让用户去找管理员）。两者合并成一个「重新登录」按钮的后果很具体：`gate_schema` 只要求登录，凡 403 都来自反代或权限中间件，此时用户会反复登录、反复 403，然后报告"接口面板登录不了"。

**判据（三段，第三段由设计文 v1.2 §5.3 补）**：

```
用户自己再点一次，这件事会不会变好？
  会        → 重试        （网络抖动、5xx）
  不会      → 换动作      （401 → 换票 = 重新登录）
  换动作也没用 → 不给按钮   （403 → 只给"找谁"）
```

**"零按钮"不是"少放一个按钮"**，而是"**这个状态没有用户可做的动作**"。硬塞一个，用户点了没变化，结论就是"系统在敷衍" —— 这比少一个按钮更伤信任。

**顺带把"今天只会 401"写清**：`gate_schema` 只调 `get_current_user`，所以当前契约请求**实际只会是 401**；403 是将来给 `/openapi.json` 加角色限制才会出现的档。写全它不是为了今天能用，而是免得那天临时拼一个"登录按钮挡 403"。

### 2.3 头部三条只读信息

```
FastAPI 契约 · v{info.version} · {操作数} 个操作 / {路径数} 个路径 · 5 分钟前刷新   [刷新契约]
```

- `info.version` 取 `doc.info.version`（当前是 `2.1.0`）。
- `操作数` = `Object.values(paths).flatMap(p => Object.keys(p)).filter(k => METHODS.includes(k)).length`（应为 46）。
- `路径数` = `Object.keys(paths).length`（应为 43）。**两个数都显示**：它们不等是 F1 的正常现象，写出来省掉一次"是不是少了一条"的怀疑。

## 三、布局与左栏

### 3.1 分组（7 组，顺序与命名以设计文 §3.1 为准）

| # | 分组 | 匹配规则 | 条数 | 内容 |
|---|---|---|---|---|
| 1 | 对话 | `/chat*` | 3 | 问答 / 流式 / 重置 |
| 2 | 知识库 | `/kbs*` | 11 | 我的库 / 文件 / 成员 / 分组 |
| 3 | 文件 | `/files/*`（不在 `/kbs` 下） | 3 | 审批 / 驳回 / 删除文件 |
| 4 | 管理 | `/admin/*` | 19 | 用户 / 文档 / 矩阵 / 审计 |
| 5 | 开放接口 | `/open/v1*` | 5 | X-API-Key 通道 |
| 6 | 认证 | `/auth*` | 3 | 登录 / 注册 / 我是谁 |
| 7 | 诊断 | `/`、`/health` | 2 | 健康检查（不属于任何前缀的孤儿路由） |
| | **合计** | | **46** | |

**顺序 = 使用频率，不按字母序**（设计文 §3.1）：「认证」只在排障时看，「诊断」置底但**不隐藏**（`/health` 是运维点开面板要的第一条）。

> **本文 §6.3 的全表按"前缀 / 代码顺序"排，与左栏的频率序不同。** 两个顺序各有用途：左栏用于**找**，全表用于**和 `main.py` 对账**（按代码顺序数，才不会漏）。验收时按"每组条数"对，不按组号对。

**为什么 `files` 单独成组而不是并进 `kbs`**：文件审批（`/files/{fid}/approve`）是**跨库**的（路径里只有 `fid`，没有 `kb_id`），并进 `kbs` 会让人以为要先选库。

**为什么「开放接口」的组名不写 `open`**：这一组全部**不可试调用**（§5.3），组名必须直说它是"对外的另一个通道"，否则会被当成"另一批普通接口"。

### 3.3 左栏键盘

| 键 | 行为 |
|---|---|
| `/` | 聚焦筛选框（仅在焦点不在输入框/编辑区时） |
| `↑` `↓` | 在**全部可见条目**间移动（跨分组；分组头不参与） |
| `←` `→` | 折叠 / 展开当前分组 |
| `Enter` | 选中并渲染右侧 |
| `Esc` | 有筛选词 → 清空筛选；无 → 焦点回筛选框（不清空选中） |
| 分组头 `Space` | 折叠切换（分组头自身可聚焦，`aria-expanded`） |

**焦点与选中的分离**：`↓` 只移动焦点（预览），`Enter` 才换成"选中"并改 URL。理由：改 URL 会 `pushState`，长按 `↓` 穿过 20 个接口会写 20 条历史，后退键就废了。

```
│    {                                                              │
│      "ok": true, …                                                │
│    }                                                              │

```

### 4.1 ① 标题段

| 行 | 内容 |
|---|---|
| 1 | 方法签 + 路径 + 权限徽标（`公开` / `登录` / `管理员` / `仅超级管理员` / `API-Key`） |
| 2 | `operation.summary` **原样显示，不翻译**（FastAPI 从函数名生成，实测是 `My Kbs` / `Chat` / `Admin Delete Kb` / `File Approve`）。理由见设计文 §3.4：前端维护中英映射表 = 造第二份真相。无 summary 时显示 `—`，不许编中文 |
| 3 | 禁用原因条（仅禁用项；文案见 §7） |

### 4.2 ② 参数表（严格按契约的 `in`）

| 列 | 内容 |
|---|---|
| 位置 | `path` / `query` / `header`（三段分表；空段不渲染标题，只写一行 `无参数`） |
| 名称 | `--mono`，必填带 `*`（`required: true` 或 `in: path` 恒必填） |
| 输入 | 见下"控件选择" |
| 类型/约束 | `integer` / `string` / `boolean` / `array`；`min`/`max`/`maxLength` 有则显示（如 `1–31 字符`） |
| 默认值 | 契约有 `default` 时预填，并置灰显示 `默认` 标记；用户改动后标记消失 |

**控件选择规则（三条，不自由发挥）**：

1. `schema.enum` 存在 → `<select>`（当前 46 个操作里没有 enum，但这是零成本兼容）。
2. `type === "boolean"` → `<select>`：`不发送` / `true` / `false`。**三选项**，因为"不发送"与"发 false"是两个语义。
3. 其余 → `<input>`（`type=number` 仅当 `integer/number`），`inputmode` 同步（移动端数字键盘）。

**path 参数：行内输入框 + 顶部 URL 实时替换**（两者同步，不是二选一）。

- 理由：面板的产出物有一半是"我要把这条 URL 贴给别人/贴到 curl 里"，所以**解析后的完整 URL 必须可见**；而填写动作发生在参数表里（有类型、有必填提示）。"点一下替换 URL 里的 `{id}`" 要求用户在字符串里找占位符，是可编辑文本当表单用的反模式。
- 未填的 path 参数：请求预览里该段保持 `{kb_id}` 并标 `--amber`，发送按钮 `disabled`，`title` 写 `还有 1 个路径参数未填`。

### 4.3 ③ 请求预览与参数重置

- 预览行：`{METHOD} {完整 URL}`，`--mono` 13px，超宽横向滚动（不换行，换行会看错 `/`）。
- 「复制 URL」：复制**含 query 的完整 URL**，不含 token。
- 「重置参数」：所有输入回默认占位、body 回生成的示例、清空上次响应。**不做二次确认**（可重填，成本 3 秒）。
- 有 query 参数时，预览里的 query 顺序 = 参数表顺序（不是字母序），这样"表里第 2 行"和"URL 里第 2 段"对得上。

### 4.4 requestBody：**必须写 mini resolver**（约 20 行），不许直接给 `{}`

**裁定**：写 resolver，不退化。理由：`POST /auth/login`、`POST /chat`、`POST /admin/kbs`、`PATCH /admin/kbs/{kb_id}` 的 body 全是 `$ref`（Pydantic 模型），直接给 `{}` 等于让管理员回到"读源码"。而解引用就是 20 行，一次写完 46 个接口全受益。

```js
// 只生成结构，不生成"真数据"：占位一律类型零值（见下"零值原则"）
function exampleOf(schema, root, depth = 0, seen = new Set()) {
  if (!schema || depth > 3) return null;
  if (schema.$ref) {
    if (seen.has(schema.$ref)) return null;          // 循环引用：截断，不递归爆栈
    const name = schema.$ref.split("/").pop();
    return exampleOf(root.components.schemas[name], root, depth + 1,
                     new Set(seen).add(schema.$ref));
  }
  if (schema.anyOf || schema.oneOf)                   // 联合类型取第一个分支
    return exampleOf((schema.anyOf || schema.oneOf)[0], root, depth + 1, seen);
  if (schema.type === "object")
    return Object.fromEntries(Object.entries(schema.properties || {})
      .map(([k, v]) => [k, exampleOf(v, root, depth + 1, seen)]));
  if (schema.type === "array") return [exampleOf(schema.items, root, depth + 1, seen)];
  if (schema.type === "integer" || schema.type === "number") return 0;
  if (schema.type === "boolean") return false;
  return "";                                          // string / 无类型
}
```

**零值原则（安全默认）**：占位永远是 `"" / 0 / false / []`，**不是** `"示例"` / `1` / `"张三"`。理由：

- `1` 会命中**真实记录**：`DELETE /kbs/1` 预填 1 = 把枪口对准默认库；`POST /kbs/{id}/members` 预填某用户名 = 可能真给人授权。
- `"示例"` 会**真写进库**：`POST /admin/users/{u}/group` 传 `group="示例"` 会建出一个不存在的分组名，污染矩阵。
- 零值的结果是 **400/404 + 一句清楚的 detail**，这恰好是面板该展示的东西（"参数填错时后端怎么说"），而不是一次误写。

**发送前校验**（只拦"必然 422/400"的三类，不做业务校验）：必填字段值为 `""`/`null`/`undefined`/`[]` → 禁用发送 + 该行标红 + `title` 写 `{字段名} 不能为空`。`0` **放行**（它是合法整数，且 `id=0` 打不中任何记录，安全）。

**body 编辑器**：`<textarea>` + `--mono` 13px + `min-height: 140px`，`spellcheck=false`。
- 用户改坏 JSON → 失焦即校验，`JSON 格式错误：{message}`，发送禁用（**不自动格式化**，自动改用户的字会让人不敢改）。
- 「格式化」按钮（手动触发，2 空格缩进）。
- 切换接口：**清空**参数与 body（不回填上一个接口的残值）。理由：把 A 接口的 body 带到 B 接口，是"看起来发了、其实发错"的经典事故。

### 4.5 ④ 发送

| 项 | 规格 |
|---|---|
| 按钮文案 | `发送请求`；加载中 `请求中…` + 转圈 + 秒级计时（`1.2s`） |
| 按钮颜色 | GET → `--blue` 描边；POST/PATCH → `--blue` 实底；DELETE → `--red` **文字按钮**（红底留给确认框） |
| 禁用条件 | 路径参数未填 / body JSON 非法 / 必填为空 / 有请求在飞 / 接口本身禁用 |
| 并发 | **同一时刻只允许 1 个试调用**。理由：面板用于核对结论，两个响应互相覆盖会让"哪条是哪条"变成猜谜。第二个请求发起时按钮 `disabled` 并 `title` 写 `上一个请求还没结束` |
| 取消 | 请求中显示「取消」（`AbortController`），取消后响应区显示 `已取消`（不是"失败"，也不是空白） |
| 超时 | 默认 **20s**；`/chat` 类 **90s**（一次完整 RAG 链路），`/admin/rebuild` **30s** |
| 自动重试 | **绝不自动重试**，尤其 POST/PATCH/DELETE。超时文案见下 |

**超时文案（写死，别改成"请求失败"）**：

```
请求超时（20s）
接口可能仍在服务端执行。写操作（POST/PATCH/DELETE）不要立刻重试，
先去对应页面确认结果，再决定是否重发。
```

理由：`POST /admin/rebuild` 超时但服务端已在重建，重试 = 两次重建；`DELETE /kbs/7` 超时可能已删，重试 = 404，用户会以为"删除失败了"。

### 4.6 ⑤ 响应

```
[200]  342 ms · 1.2 KB                       [复制 JSON] [展开全部]
──────────────────────────────────────────────────────────────
{
  "id": 3,
  "name": "财务制度库",
  …
}
```

| 项 | 规格 |
|---|---|
| 状态码签 | `2xx` `--teal` / `3xx` `--blue` / `4xx` `--amber` / `5xx` `--red`；网络错误显示 `—` + `网络错误`；超时显示 `—` + `超时` |
| 耗时 | 客户端测得（`performance.now()` 差），整数 ms，>1000 显示 `1.34 s` |
| 大小 | `Content-Length` 或 `blob.size`；>100KB 时高亮（提醒"这接口返回很大，别在面板里反复点"） |
| body | 原文渲染，**保留键序与缩进**；超过 **40 行**折叠为前 20 行 + `展开全部（N 行）`（阈值与形态见设计文 §4.6）。行号槽只读、不可选中 |
| 折叠 | 只有"整体折叠/展开"，**不做可点开的 JSON 树**。理由见下 |
| 复制 | 复制的是**原始响应文本**（格式化后的，不是压缩的），不含状态行 |
| 非 JSON | 直接显示原文 + 顶部一行 `响应不是 JSON（content-type: text/html）` |

**为什么不做交互式 JSON 树**：这个面板的核心产出是"复制一段响应/看清一个字段"。树形结构会（a）丢掉键序（管理员常靠键序判断 Pydantic 序列化顺序），（b）让 `Ctrl+A / Ctrl+C` 复制到一堆折叠标记，（c）在 100KB 响应上卡。**可复制的原文 > 好看的树**。

**错误响应也是成功的一次调用**：4xx/5xx 不弹 toast、不标红整块，只在状态码签上着色 + body 原样展示。`detail` 就是管理员要的答案；把它塞进 toast 2.5 秒后消失是最糟的处理。

## 五、鉴权四层与锁定态

### 5.1 为什么不能用 openapi 里的 security（重要）

FastAPI 只有用 `Security(HTTPBearer())` 才会写 `components.securitySchemes`；本项目全用 `Depends(get_current_user)`（F5），所以：

- `doc.components.securitySchemes` **不存在**；
- 没有任何 operation 带 `security` 字段。

**结论：不要读 security 字段，也不要在前端"猜"它有没有。** 用 5 条路径规则，规则写在一处常量，可 grep 对账：

```js
const AUTH_RULE = [
  { test: p => p === "/" || p === "/health",                     tier: "public"  },
  { test: p => p === "/auth/login" || p === "/auth/register",    tier: "public"  },
  { test: p => p === "/admin/search",                            tier: "super"   },
  { test: p => p.startsWith("/admin/"),                          tier: "admin"   },
  { test: p => p.startsWith("/open/"),                           tier: "apikey"  },
  { test: () => true,                                            tier: "jwt"     },
];
```

### 5.2 四层 + 一个特例的呈现

| tier | 徽标 | 试调用 | 说明文字 |
|---|---|---|---|
| `public` | `公开` | ✓ 不带 `Authorization` | `无需登录` |
| `jwt` | `登录` | ✓ 带 `Authorization: Bearer {kb_jwt}`（`authHeaders()`，`app.js:37`） | `以当前登录身份调用` |
| `admin` | `管理员` | ✓ 同上 | `需要系统管理员（admin/superadmin）` |
| `super` | `仅超级管理员` | ✓ 同上；非超管点发送 → 预判拦截 | `只有 superadmin 能调；admin 会得到 403` |
| `apikey` | `API-Key` | ✗ **锁定** | 见 §5.3 |

**`super` 的预判拦截**：`me.role !== "superadmin"` 时，发送按钮改为锁定态，`title` 写 `该接口要求 superadmin，当前身份是 admin`。理由：让用户点一下拿 403 也算"能验"，但**明知必败还发一次**只是浪费一次审计记录；而 403 的原文可以在「审计日志」页看到。

### 5.3 `/open/v1/*` 全部锁定（按 locked 判据定性，不是 forbidden）

**判据（交互规范 §5.1.3）**：`locked` = 挡住的是**能力**、钥匙在系统里某处 → 画 + 告诉钥匙在哪；`forbidden` = 挡住的是**权利**、谁都解不开、规则在别处没有落点 → 画 + 写规则原句；`unreachable` = 状态终局 → 不画。

**这里落 `locked`**（与《接口面板设计》v1.1 §5.1 一致："按后台 §3.12 走 locked 分支（给钥匙在哪），不是 forbidden"）：

- 挡住的是能力不是权利：密钥在 `settings.admin_api_key`（服务端 `.env` 的 `ADMIN_API_KEY`），**存在、可配置、只是不在浏览器里**。管理员补齐/领取钥匙后这条路就通了 —— 这就是 `locked` 的定义。
- 判据反问："删掉这个锁定条，用户还能从别处读到这条规则吗？" —— 不能。`/open/*` 的调用方是外部系统，后台其它页没有第二处提到 `X-API-Key`。
- 所以：**画**，路径后带 `🔒`，右侧无发送按钮，原因条给**钥匙在哪**：

```
该接口需要 X-API-Key（服务端 ADMIN_API_KEY），浏览器不持有此密钥，故不能在线试调用。
请用 curl 或调用方系统验证；密钥只配置在服务端 .env。
```

- 徽标 `API-Key` 用 `--amber` 描边（不是红：红是"危险"，这里是"缺凭证"）。
- 参数表**照常渲染**（`group` / `status` 等 query 仍可读），只把 ④ 发送区换成锁定条。**读契约与能不能执行是两件事**，锁的是后者。

### 5.4 401 的统一处理（取契约与试调用两种来源）

两个地方都会 401，**处理不同档**：

| 触发点 | 表现 | 为什么不一样 |
|---|---|---|
| 取契约 `GET /openapi.json` 401（进页签即发生） | **整页** `登录已过期` + **只给「重新登录」**（§2.2）。**不给「重试」** | 页面还没有任何内容可留，重试恒 401 |
| 试调用返回 401（点「发送」之后） | 与 `api()` 封装一致：清 `kb_jwt`/`kb_user` → `showAuth()`（`showAuth`，`app.js:45`）。跳转前用 `toast("登录已过期，请重新登录", "err")` 说一句。**不要**在响应区写"token 过期"然后让发送按钮继续可点 —— 后续每次点都是 401，用户会以为面板坏了 | 页面上还有刚填的参数，但**token 已死，那些参数也发不出去**，所以"丢掉参数换一次干净的登录"是划算的；不划算的是"留着参数让用户继续点" |

共同点：**都不提供"原地重试"**。401 是"身份没了"，不是"请求没成" —— 这两件事在界面上必须长得不一样。

## 六、危险操作分级（全表 + 四类重点）

### 6.1 复用交互规范 §8 的四级强度，不新造刻度

| 强度 | 形态 | 默认焦点 | 本页用到吗 |
|---|---|---|---|
| 1 | 无确认，直接发 | — | **不用**：见下"最低 2 级" |
| 2 | 确认框（取消在左，默认聚焦） | `取消` | ✓ 全部 POST/PATCH |
| 3 | 确认框 + 影响面清单 | `取消` | ✓ 批量与不可逆的写 |
| 4 | 输入 `DELETE` 才放行（`requireText`） | 输入框 | ✓ 4 个不可恢复的 `DELETE` |

**最低 2 级（与设计文 §4.5 对齐）**：本页**没有强度 1** —— 任何非 GET 操作（POST/PATCH/DELETE）至少弹一次确认。理由不是"都危险"，而是**面板里没有列表页那些上下文**：列表页删文件时你看得见文件名和上传人；面板里只有一个 `fid=42`。代价很低的确认，换来的是"点错了不会真的发生"。

**统一规则（本页特有）**：确认框里必须出现**将要发出的真实请求**（方法 + 解析后的 URL + body 前 400 字），因为面板的确认是"对线路层的确认"，不是"对业务的确认"。

```
① 标题：「删除知识库 · DELETE /admin/kbs/7」
② 请求：DELETE http://host/api/admin/kbs/7        （--mono）
③ 后果：「该库的文件索引与成员/分组授权将一并失效，问答不再引用其中文档。」
④ 不可逆：「此操作不可撤销，界面内无法恢复。」
⑤ 按钮：取消（左，默认焦点） + 删除（右，.btn-danger，输入 DELETE 前 disabled）
```

**安全要求（必须写进代码）**：URL / body 里含**用户输入**，拼进 `confirmDialog({body})` 的 `innerHTML` 前必须 `esc()`（`app.js:300`）。不转义 = 一个能填 `<img onerror>` 的参数就能在管理员页面上执行脚本。

**强度 4 的输入词统一为 `DELETE`**（不是对象名）：面板拿不到"对象名"（`/files/{fid}` 里没有文件名，要再发一次 GET 才有），为一致性统一用 `DELETE`。对象身份由 ② 的完整 URL 承担 —— **URL 比名字更准**。

### 6.2 四类重点（任务书要求逐条给结论）

| 操作 | 强度 | 理由（必须能算出代价） |
|---|---|---|
| **`DELETE *`（6 个）** | **4（4 个）/ 2、3（另 2 个）** | **不按 HTTP 方法一刀切，按"能否一次反向请求还原"**（交互规范 §8.1 / §5.5 的判据）。不可恢复的 4 个 → 4 级：删库、删文件、删上传文档、删账号（C3：无回收站，删文件只移 `.trash/`、删库只标记 `deleted`）。可反向还原的 2 个 → 降级：`DELETE /kbs/{id}/members/{u}` 用 2（`POST members` 即可恢复）、`DELETE /kbs/{id}/groups/{g}` 用 3（一次影响一批人）。**"DELETE 恒为 4 级"是错的** —— 它会把一个两秒能撤回的动作，做成输 `DELETE` 才能执行的仪式，用户只会去别处绕过它。`DELETE /admin/documents/{name}` 额外提示"会触发索引重建" |
| **`POST /chat`** | **2** | 花一次 LLM 费用 + 5–15s 延迟 + 写入服务端会话历史。不升到 3：影响面只有 1 次问答、无持久破坏；不降到 1：**反复点 10 次就是 10 次费用**，而面板的按钮最容易连点。确认框写 `将调用一次完整 RAG 链路（路由→检索→生成），产生 LLM 费用并写入会话历史。` |
| **`POST /files/{fid}/approve`** | **3** | 影响面是"这份文档从此刻起会被所有有权限的人检索到"，且 `approve_file` 前置 `status='pending'` → **不可退回**（交互规范 §8.1）。文案不许写"重建索引"——真实动作是 `add_file_to_index` **增量入库**，全量重建是 `/admin/rebuild`（这一点必须写准，否则用户会以为点了会卡 30 秒）。**与 §8 的差异要说明**：§8 把"批准入库"定为 1 级，前提是**审核弹窗已经强制看了内容**；面板里只有一个 `fid`，**看不见文件内容**，所以必须升到 3 级，并在确认框写 `面板内看不到文件内容，请先在知识库详情页核对这份文件。` |
| **`POST /open/v1/users`（+ `/batch`）** | **不适用（锁定）** | 浏览器无 API-Key，**打不出去**（§5.3）。若将来通过服务端代理开放，按 **4** 处理：`auto_approve=true` 等于"创建即激活"，批量 `action=delete` 一次删 500 个账号（`max_length=500`），代价无法在界面上估算 |

### 6.3 46 个操作全表（按组，可直接对照左侧列表数一遍）

## 八、键盘与焦点

### 8.1 Tab 顺序（一条线性路径）

```
① 页头「刷新契约」
② 左栏筛选框
③ 左栏分组头 1 → 条目…（分组内顺序）
④ 参数表：path 1 → path 2 → query 1 → …
⑤ body textarea（有 body 时）→ 「格式化」
⑥ 「复制 URL」 → 「重置参数」
⑦ 「发送请求」
⑧ 响应区：「复制 JSON」 → 「展开全部」
```

**左栏不放 Tab 流里**：46 个条目 + 7 个分组头会让 Tab 穿过 50 多个元素才到右侧。左栏用 `↑↓` 导航（§3.3），只把**筛选框**和**当前选中项**放进 Tab 流（`tabindex="0"`，其余 `tabindex="-1"`）。这与交互规范 §9.1「一条线性路径」不冲突：左栏是一个复合控件（listbox），不是一列独立按钮。

### 8.2 Enter / Esc / 组合键

| 位置 | Enter | Esc | 其他 |
|---|---|---|---|
| 左栏筛选框 | 选中第一条匹配项 | 清空筛选 | `↓` 进入列表 |
| 左栏条目 | 选中 | — | `↑↓` 移动，`←→` 折叠分组 |
| **参数输入框** | **焦点移到下一个参数**（最后一个 → body / 发送按钮）。**绝不发送** | 恢复该字段默认值 | `Tab` 正常前进 |
| body textarea | **插入换行**（不发送、不跳走） | 不关闭页签 | `Ctrl/Cmd+Enter` = 发送 |
| 发送按钮 | 发送（含确认流程） | — | `Ctrl/Cmd+Enter` 全局 = 发送 |
| 确认框 | 输入值正确时 = 确认 | 取消并回触发按钮 | 危险操作默认焦点在「取消」/输入框（`app.js:966-970` 已实现） |

**"Enter 不发送"是硬规则**：参数表里有 5 个输入框时，用户按 Enter 的本能是"下一个"。若 Enter 触发 `DELETE /admin/kbs/7`，那是面板自己制造的事故。**发送必须是显式动作（点按钮或 Ctrl+Enter）。**

**Esc 不关闭页签**：页签是路由（`#admin/api`），Esc 关闭会让人以为"退出了面板"；Esc 在本页只处理"清筛选 / 关确认框 / 取消展开"。

### 8.3 焦点管理

| 场景 | 焦点去哪 |
|---|---|
| 进入 `#admin/api` | 左栏筛选框（不是页头：本页的第一个动作是"找接口"） |

## 十一、复制为 curl（一个容易做错的高价值动作）

```
curl -X DELETE 'http://host/api/admin/kbs/7' \
  -H 'Authorization: Bearer $KB_JWT' \
  -H 'Content-Type: application/json'
```

| 规则 | 说明 |
|---|---|
| `Authorization` 写 `$KB_JWT` | **绝不**复制真实 token：剪贴板会被贴进群聊/工单，等于泄露一次有效凭证 |
| 有 body 才加 `Content-Type` | GET/DELETE 无 body 时不加，否则复制到终端会多一个误导性的头 |
| URL 用单引号包裹 | 防 `&` 被 shell 解释（query 参数常见） |
| body 用 `-d '{...}'` 单行 | 与面板里的格式化 JSON 不同：终端里多行 `-d` 要转义，容易粘坏 |

「复制 JSON」（响应区）与「复制 URL」都不含 token，可放心分享。

### 12.2 四态 × 区块

| 区块 | 加载 | 空 | 错误 | 无权限 |
|---|---|---|---|---|
| 左栏列表 | 6 条骨架（`aria-busy`） | `没有匹配的接口`（筛选为空） | 整页错误卡（左栏不单独报错） | 页签不可达：非管理员访问 `#admin/api` → 回 **`#chat`（门户）** + toast `需要管理员权限`（`applyRoute` 的保护已有，**只改落点 hash**：门户上线后 `#home` 不再存在，兜底必须落到 `#chat`） |

**"未发送过"的空态必须有文案**：一块纯白区域会让人以为"响应区坏了"，而它只是还没被用过。

**为什么 401 不算进"错误"这一列**（v1.2）：错误给的是「重试」，401 给的是「重新登录」。两者混在一起，就会出现"点重试五次全 401"的经典事故。四态不变，401 是**错误态里唯一不给重试的子态** —— 判据只看一条：**这个动作用户自己再点一次会不会变好？**会 → 重试；不会 → 换动作（登录）。

### 12.3 契约失败的两个落点与零按钮的三条断言（v1.2 补，容易漏）

同一个错误有**两个渲染位置**，动作按钮必须共用同一套类与同一套判定：

| 位置 | 何时出现 | DOM |
|---|---|---|
| **整页错误块** | 首屏就取不到契约（左栏此时是骨架） | `.api-blank.api-errblk` → `.api-err-act`（包着动作） |
| **顶部错误带** | 手里已有上次的清单，点「刷新契约」失败；详情照常可读 | `.api-errbar`（flex 行，`role="status"`） |

**通则：同一动作在多处渲染，必须共用一个容器类**（这里是 `.api-err-act`）。理由是**验收会被它坑**：如果错误带的动作裸插（没有 `.api-err-act`），那么 `.api-err-act button` 的断言会查到 **0 个** —— 它"通过"了，但通过的理由是"没查到容器"，不是"真的零按钮"。**假通过比失败更危险**，它会让 403 给「重新登录」的 bug 在第二个场景里漏过去。

**间距归父级，不归容器类**（v1.2，visual-architect-2 修正了我的写法）：`.api-err-act` 不该自带"只对某个父级成立"的间距 —— 否则第三个落点还要再写一次 `margin-top: 0`，覆盖越积越多，最后没人敢动这个类。

```css
.api-err-act { margin-top: 0; }                        /* 默认不带间距 */
.api-errblk .api-err-act { margin-top: var(--sp-4); }  /* 整页错误块才需要 */
.api-errbar .api-err-act { flex: none; }               /* 错误带里不被压缩 */
```

**零按钮还要处理空容器**（比 margin 更容易漏）：403 时 `apiErrActionHTML()` 返回空串，但 `<div class="api-err-act">` 是**外层**、照样渲染 —— 空 div 在 `.api-errbar` 的 `gap: 12` 里仍占一格，右侧多出 12px 空白；若 margin 没归零，还会把条撑高 16px。

```
首选：渲染函数在没有动作时根本不输出容器（apiErrActionHTML() 返回 "" 时，外层 div 一起不输出）
兜底：.api-err-act:empty { display: none; }
```

**验收用可量的数判死，不靠"看起来正不正"（高度这一列仅适用错误带）**：

| 场景 | `.api-errbar` 高度 | 拆解 |
|---|---|---|
| 401（一个「重新登录」） | **50** | 32（`--btn-h-sm`）+ 16（padding 8×2）+ 2（边框） |
| 403（零按钮） | **36** | 18（文案行高）+ 16 + 2 |
| **若 16px 漏进 flex** | **66 / 52** | 各自多 16 —— 出现这两个数就一定是间距没归父级 |

**这组数只对错误带成立**：整页错误块 `.api-errblk` 用的是 `.api-blank`（`display:flex; justify-content:center; min-height:260px; height:100%`，`app.css:2383-2386`），它的高度由右栏撑满、永远不是 36 —— 在它身上量高度会得到 260+，但**那不是"间距没归位"，是它本来就没有"条"这个概念**。

再加一条：403 时 `.api-err-act` 的 `getBoundingClientRect().width` 必须是 **0**（空容器即使用 `:empty` 藏起来，只要还占位就不会是 0）。

**这三条是链，不是清单**（visual-architect-2 定的验收顺序）：① `button` 数 = 0 → ② 容器 `width` = 0 → ③ 条高 = 36 **且容器 `marginTop` = 0**。**换了顺序会互相掩盖**：若按钮还在（32 高），条高量到 **50** —— 而 50 恰好是 401 的正确值，你会以为"这是 401 场景，正常"。所以**前一条是后一条的前提**，不是并列选项；少跑第一步，后面全是假通过。

> ③ 里那条 `marginTop` 不是"再加一道保险"，而是**高度断言本身不完备**：高度只回答"最后多高了"，若那 16px 被负 margin / 行高变化 / 按钮改版部分抵消，高度仍可能是 36，而间距并没归父级 —— 此时高度断言失明。`marginTop` 只回答"这个容器自己带不带间距"，是高度的**必要条件**，不是它的补集。两条看起来互补，实际一条失效时另一条不会替它说话。
>
> **根源：和值不能反推加数**（visual-architect-2 补）。高度是**多个因子的和**（`padding` + 行高/按钮 + 边框 + 混进来的 `margin`），`marginTop` 是**单个加数**。和值相等不意味着加数相同 —— 3+5 与 4+4 都是 8。所以"量总高"与"量某个 margin"测的是**不同粒度**，不是同一件事的两次测量：**前者天然不携带分量信息**。这条可推广到所有"量总宽 / 总高"的验收 —— 用和值做断言时，必须能说出"哪些加数可能变"。**列不出来，就说明这条断言现在靠的是运气**（而不是"下次注意"）。

**适用范围**：①② 两个位置都跑（整页错误块 + 错误带）；**③ 只在错误带上跑** —— 整页错误块没有条，量它只会得到一个与 36 无关的数。

**为什么"只有跟视口无关的数才配当断言"**（v1.2，visual-architect-2 补）：`.api-blank` 是 `min-height: 260px` **加** `height: 100%` —— 短视口被右栏压低、长视口被拉高，**每换一次窗口它都会变**。拿这种数当基准，验收会随环境漂移，最后没人信它。

错误带相反：它的高度只由 `padding + 行高/按钮 + 边框` 决定，与视口无关，是**真正的常量**（50 / 36 / 66 / 52）。这不是"错误带更好量"，而是**只有错误带上的高度才是一条可复现的断言** —— 这条判据可以推广到所有"用尺寸做验收"的地方。

**对本文的影响只有一条，但要写死**：面板取契约必须带 JWT（§2.1），并因此**多出一个状态** —— JWT 过期时点「接口」页签会 401。此时整页显示 `登录已过期` + **只给「重新登录」、绝不给「重试」**（§2.2）。理由：过期 token 重试恒 401，给重试按钮等于把"会话掉了"伪装成"网络抖了一下"，用户会连点五次然后报障。

**顺带说明为什么当初"不补假权限"是对的**：如果 v1.1 时前端自己做了"未登录就隐藏路径"，后端这次上锁后前端还要拆掉那段逻辑（否则登录了反而看不到）；而现在前端零改动就生效 —— 因为前端从头到尾只做了一件事：**该带的凭证带上，不该显示的失败原因说清楚**。

**同时要删掉的一句话**：v1.1 里我写过"§5 的四层鉴权是**执行层**的锁、不是**展示层**的遮"。现在展示层也锁了（未登录拿不到契约），这句话不再成立，已删。`/open/v1/*` 的 `locked` 定性不受影响 —— 那 5 条锁的是**能不能调**，与**能不能看见**是两件事。

### 15.5 v1.2 采纳设计文的三条（都属"写错不报错"的那一类）

| # | 规范 | 本文落点 | 为什么必须写死 |
|---|---|---|---|
| 1 | 容器查询宿主要挂在**内层**（`#paneApi`：`container-type: inline-size; container-name: api`，`app.css:2177-2178`），不是挂在带页面内边距的外层 `#viewAdmin` | §14 布局验收 | 挂错一层，量到的是"外框"而不是"列宽"，**阈值会整体偏一档且不报错** —— 表现是"在某个宽度下布局忽然变了"，查起来极慢 |
