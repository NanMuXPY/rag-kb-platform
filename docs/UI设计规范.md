# UI 设计规范 · 技术支持知识库

> 版本 v3.0 ｜ 适用：`frontend/app.css`（961 行）｜ 更新：2026-11-02
>
> 这份文档不是审美偏好清单，而是**这套界面为什么长这样、改的时候按什么规则改**的依据。
> 所有数值都能在 `app.css` 的 `:root` 里找到对应令牌，代码与文档一一对应。

## 一、现状诊断（改之前实测到的）

在写规范前先把 `app.css` 扫了一遍，问题集中在「系统缺失」而不是「配色难看」：

| 维度 | 实测 | 问题 |
|---|---|---|
| 字号 | **15 种**：10 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 15.5 / 16 / 17 / 19 / 26 | 有 5 个半像素级别（11.5 / 12.5 / 13.5 / 14.5 / 15.5），肉眼无法区分，纯粹是逐次微调留下的沉淀物 |
| 圆角 | **9 种**：3 / 4 / 5 / 6 / 7 / 8 / 9 / 10 / 14 | 同为「小控件」却出现 5 种圆角，气质不统一 |
| 内边距 | **18+ 种组合**（9px 11px、9px 12px、9px 15px、9px 16px…） | 没有间距刻度，靠手感取值 |
| 断点 | 3 处分散：474 行（720px）、566 行（860px）、954 行（720px） | **两个 720px 块分居文件首尾**，后者静默覆盖前者——上次移动端汉堡按钮「永远不显示」的 bug 就是这个结构导致的 |
| 颜色 | 12 处硬编码（`#FDFDFB`、`#2A5C9E`、`#EAD9B0`…） | 未走令牌，改主题时漏改 |

结论：**视觉方向是对的（档案公文风），但缺一套约束**。所以本次不重做视觉，只做「立规矩 + 收编散值」。

## 二、设计原则

四条，按优先级排序。冲突时上位覆盖下位。

### 1. 正文优先，装饰退一步

这是给技术支持人员**每天查资料**的工具，不是官网。

- 正文行高 `1.75`、最大行宽 `72ch`（约 34 个汉字/行）
- 装饰元素（印章、纹理、朱砂线）只在**容器边缘**出现，不进入阅读区
- 纸纹透明度上限 `0.012`——只能感觉到底色有温度，不能看出条纹

### 2. 一处一色，色必有义

颜色不是装饰，是**语义**。同一个颜色全系统只有一个含义：

| 颜色 | 唯一含义 | 禁止用于 |
|---|---|---|
| 墨蓝 `#1E4E8C` | 主操作 / 可点击 | 装饰性标题 |
| 松绿 `#22705F` | 成功 / 已激活 | 普通强调 |
| 朱砂 `#B5402A` | 印章品牌 / 危险 / 拒答 | 普通强调、警告 |
| 琥珀 `#8A5A00` | 待处理 / 分组签 | 错误提示 |

警告与错误**必须区分**：琥珀是「等你处理」，朱砂是「出了问题或被拒绝」。

### 3. 边界靠线，不靠阴影

档案感来自**清晰的线和留白**，不是浮起来的卡片。

- 分区用 `1px solid var(--line)`，不用 box-shadow
- 阴影只给「真的浮在页面之上」的东西：弹窗、抽屉、下拉
- 卡片默认零阴影；hover 时最多 `0 1px 2px`

### 4. 动效只做一件事：交代因果

- 元素进场 = 它从哪来（抽屉从左侧推出、消息从下方浮入）
- 时长 `160–260ms`，统一缓动 `cubic-bezier(.22, 1, .36, 1)`
- 只动 `transform` / `opacity`，绝不动 `width` / `height` / `top`
- 尊重 `prefers-reduced-motion: reduce`，全部降为 `0.01ms`

## 三、设计令牌

全部定义在 `app.css` 的 `:root`。**写样式时禁止出现裸数值**，一律引用令牌。

### 3.1 色彩

```
/* 面 */
--paper      #F6F4EE   页面底（暖纸）
--paper-2    #EFEBE0   比底深一档：输入框底、表头、hover
--surface    #FFFFFF   卡片 / 气泡 / 弹窗

/* 字 */
--ink        #22303F   正文
--muted      #6E7681   次要说明、时间戳
--ink-soft   #4A5666   次级正文（长引用、补充说明）

/* 语义 */
--blue       #1E4E8C   主操作      --blue-dk #173D70 (hover)  --blue-bg #EDF2FA
--teal       #22705F   成功/激活   --teal-bg #EAF4F0
--red        #B5402A   品牌/危险   --red-bg  #FAEFEC
--amber      #8A5A00   待处理      --amber-bg #FBF3E2

/* 线 */
--line         #E4E0D5  常规分隔
--line-strong  #D3CDBD  表格、输入框描边、需要更明确的分区
```

**对比度硬指标**：`--ink` 对 `--paper` = 11.8:1，`--muted` 对 `--paper` = 5.1:1，均过 WCAG AA。
`--red` 对白 = 5.0:1（可作正文前景）；**朱砂不能做浅底上的小字**（`--red` on `--red-bg` 仅 4.3:1，只允许 ≥14px 半粗）。

### 3.2 字号（8 级刻度）

原 15 种收敛为 8 级，半像素级别全部并入整数：

| 令牌 | 值 | 用途 | 原值归并 |
|---|---|---|---|
| `--fs-2xs` | 11px | 极小标记、角标 | 10, 11, 11.5 |
| `--fs-xs` | 12px | 辅助说明、时间戳、分组签 | 12, 12.5 |
| `--fs-sm` | 13px | 次要正文、表格内容、按钮小号 | 13, 13.5 |
| `--fs-base` | 14px | **UI 默认**（按钮/输入/列表项） | 14, 14.5 |
| `--fs-md` | 15px | 长正文（回答气泡、文档预览） | 15, 15.5 |
| `--fs-lg` | 16px | 小标题、弹窗标题 | 16, 17 |
| `--fs-xl` | 20px | 页面区块标题 | 19 |
| `--fs-2xl` | 26px | 登录页标语、空状态主文案 | 26 |

配套：
- 行高：`--lh-tight 1.35`（标题）/ `--lh-base 1.7`（UI）/ `--lh-read 1.75`（回答正文）
- 字重只用 **400 / 500 / 600 / 700** 四档，不用 300 与 800
- 中文标题用 `--serif`，UI 与正文一律 `--sans`；数字与代码用 `--mono`

### 3.3 间距（4px 基准）

`--sp-1 4px` / `--sp-2 8px` / `--sp-3 12px` / `--sp-4 16px` / `--sp-5 20px` / `--sp-6 24px` / `--sp-8 32px` / `--sp-10 40px`

规则：
- 组件内边距只用 `--sp-*` 组合，**不再出现 7px / 9px / 11px 这种奇数**
- 元素之间（同一组内）用 `--sp-1/2`；组与组之间 `--sp-3/4`；区块之间 `--sp-6/8`
- 例外：图标与文字的间隙允许 `6px`（视觉重心补偿），写死为 `--sp-icon 6px`

### 3.4 圆角（4 级）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--r-sm` | 4px | 徽标、小标签、代码块 |
| `--r-md` | 8px | **默认**：按钮、输入框、卡片、气泡 |
| `--r-lg` | 12px | 弹窗、抽屉内的大面板 |
| `--r-full` | 999px | 胶囊：状态点、计数徽章 |

印章是品牌特例，用 `--r-seal 6px` 加内描边模拟印面。

### 3.5 阴影（3 级）

```
--shadow-card  0 1px 2px rgba(34,48,63,.05)                      // 卡片 hover
--shadow-pop   0 4px 12px rgba(34,48,63,.10), 0 16px 48px rgba(34,48,63,.14)   // 弹窗
--shadow-rail  -2px 0 16px rgba(34,48,63,.10)                    // 移动端抽屉
```

### 3.6 动效

```
--ease       cubic-bezier(.22, 1, .36, 1)   // 出场
--ease-inout cubic-bezier(.4, 0, .2, 1)     // 状态切换
--dur-fast   160ms   // hover、按钮反馈
--dur-base   220ms   // 元素进场、抽屉
--dur-slow   260ms   // 页面级切换
```

## 四、布局

### 4.1 骨架

```
┌───────────────────────────────────────────┐
│  rail 248px  │  main (1fr)                │
│  会话列表     │  topbar 56px              │
│  文件中心     ├───────────────────────────┤
│  管理面板     │  view（问答/知识库/控制台）│
│  账号区       │                           │
│              ├───────────────────────────┤
│              │  composer（仅问答视图）   │
└───────────────────────────────────────────┘
```

- 整页 `height: 100vh` + `overflow: hidden`，只有 `view` 内部滚动（问答为消息区滚动，其余为整页滚动）
- 版心：内容区最大 **880px** 居中（`--content-max`），超宽屏靠留白，不拉满

### 4.2 断点（只留 2 个）

| 断点 | 触发 | 变化 |
|---|---|---|
| `≤ 860px` | 平板/小窗 | `rail` 变浮层抽屉（叠在上面），topbar 出现汉堡按钮 |
| `≤ 720px` | 手机 | 抽屉 `100vw`、`view-pad` 收到 14px、输入字号 16px（防 iOS 聚焦缩放）、隐藏 `scope-note` 等次要信息 |

**结构约束**：所有断点规则集中在文件末尾一个 `@media` 块里，**同断点只允许出现一次**。
原因见踩坑 #42：分两处写 720px 块，后写的静默覆盖前写的，直接吃掉了汉堡按钮。

### 4.3 触控目标

- 移动端所有可点元素最小 **40×40px**（视觉可小，用 `::after` 扩热区）
- 相邻可点元素间距 ≥ `--sp-2`

## 五、组件规格

### 按钮

| 类型 | 背景 | 文字 | 描边 | 高度 |
|---|---|---|---|---|
| 主按钮 `.btn-primary` | `--blue` | `#FFF` | 无 | 36px |
| 次按钮 `.btn-ghost` | transparent | `--ink` | `--line-strong` | 36px |
| 文字按钮 `.uact` | 无 | `--blue` | 无 | 28px |
| 危险 `.uact.danger` | 无 | `--red` | 无 | 28px |

- 圆角 `--r-md`，内边距 `--sp-2 --sp-4`，字号 `--fs-base`，字重 500
- hover：主按钮 `--blue-dk`；次按钮底色 `--paper-2`
- disabled：`opacity .45` + `cursor: not-allowed`，**不移除边框**（保持占位不跳动）
- 加载中：文字替换为「处理中…」并禁用，不显示旋转图标（档案风克制）

### 输入框 / 文本域

- 底 `--paper-2`，描边 `1px --line`，圆角 `--r-md`，内边距 `--sp-2 --sp-3`
- focus：描边 `--blue` + `0 0 0 3px rgba(30,78,140,.12)` 光环（**唯一允许的彩色光环**）
- 占位符 `--muted`，字号比正文小一号
- 文本域自动增高：`max-height: 160px`，超出滚动

### 消息气泡

- 用户：右上角对齐，底 `--blue`，文字 `#FFF`，圆角 `--r-md`（左下角收成 `--r-sm` 指出方向）
- 机器人：左对齐，底 `--surface` + `1px --line`，圆角同理（右下角收）
- 最大宽度 `min(680px, 78%)`
- 回答正文 `--fs-md` / `--lh-read`，Markdown 排版见 `app.css` 的 `.md` 段
- 拒答态：气泡左侧 `3px --red` 边条 + 顶部「知识库无依据 · 已拒答」徽标

### 引用档案卡 `.cite-card`

- 整行可点，左 `3px --red` 边条，圆角 `--r-md`，padding `--sp-2 --sp-3`
- 结构：`[序号]` 文档名（粗体，单行省略）/ 库名 · 片段预览（`--fs-xs --muted`，单行省略）/ 「查看片段 ›」
- hover：底色 `--red-bg`，整体右移 2px
- 点击 → `<dialog>`：标题 + 所属库 + 带红边条的原文片段（`pre-wrap`）+ 文件路径

### 徽标 / 状态点

- 状态徽标：`--fs-xs`，padding `--sp-1 --sp-2`，圆角 `--r-sm`，底色取语义 `*-bg`，文字取对应深色
- 角色圆点：8px，`--r-full`，管理员 `--red`，员工 `--line-strong`

### 表格（Markdown 与文件清单）

- 表头底 `--paper-2`，字重 600，字号 `--fs-sm`
- 单元格 padding `--sp-2 --sp-3`，描边 `1px --line-strong`
- 偶数行 `--paper`（斑马纹仅用于 ≥5 行的表）
- 窄屏：允许横向滚动，**不折行压缩**

## 六、状态与反馈

每个数据区域必须实现四态，缺一即视为未完成：

| 状态 | 表现 | 文案风格 |
|---|---|---|
| 加载 | 骨架块闪烁（不用转圈） | 无文字 |
| 空 | 居中说明 + 一个下一步动作 | 「还没有知识库，先建一个」 |
| 错误 | `--red` 文字 + 「重试」 | 写清「为什么失败 + 怎么解决」，不写「操作失败」 |
| 部分成功 | 顶部条列出失败项 | 「3 个成功，1 个失败：zhangsan 不存在」 |

**AI 回答的进度**：不使用百分比。用阶段名推进（路由 → 检索 → 打分 → 生成 → 质检），每阶段带耗时；超过 8s 追加「仍在检索，请稍候」。

**流式输出**：首字必须 ≤ 5s 出现，否则视为体验缺陷。

## 七、可访问性

- 所有 `button` 有可读文本或 `aria-label`；图标按钮必须带 `aria-label`
- 焦点可见：`outline: 2px solid var(--blue); outline-offset: 2px`，**禁止 `outline: none`**
- 颜色不是唯一信息载体：状态除颜色外必须有文字（徽标自带文字，禁止只用色点表达状态）
- 弹窗用原生 `<dialog>`，打开时焦点移入，`Esc` 关闭
- 正文对比度 ≥ 4.5:1，大字号（≥18px 或 14px 粗）≥ 3:1

## 八、发版验收清单

改完 UI 逐条勾，任一项不过不发版：

- [ ] 桌面 1440 / 1280 / 1024 三档无横向滚动、无重叠
- [ ] 手机 390 / 375 两档：顶部导航完整、汉堡可用、输入区不被裁切
- [ ] 三种角色各登一次：员工看不到「控制台」，管理员能进
- [ ] 问答全链路：提问 → 首字 ≤5s → 完整回答 → 点引用卡出弹窗 → Esc 关
- [ ] 长内容不破：超长文档名、超长用户名、40 行 Markdown 表格
- [ ] 空状态与错误态都出现过一次（不是只有正常态）
- [ ] 键盘走一遍：Tab 能到所有操作，焦点框可见
- [ ] `prefers-reduced-motion` 下无动画
- [ ] 浏览器强刷（Ctrl+F5）后无旧资源错配（版本号已 bump）

## 九、怎么加新样式（演进规则）

1. **先找令牌**：要的颜色/字号/间距/圆角必须能在第三节找到。找不到说明该扩令牌，不是该写裸值。
2. **扩令牌要改三处**：`:root` + 本文档第三节表格 + 使用处的语义注释。
3. **新组件先写进第五节**，再写 CSS。文档里没有的组件不允许出现在页面上。
4. **禁止新增断点**。真有需求先讨论能否用现有两档 + 流式布局解决（`clamp()` / `minmax()` / `flex-wrap`）。
5. **媒体查询只加在文件末尾统一块**，不在组件附近就地写。
