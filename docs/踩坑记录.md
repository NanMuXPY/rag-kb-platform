## 详述（挑重点展开）

### #1-#3 三道闸：E0→E1 的核心收益

- **现象**：E0 阶段检索为空（sources=[]）仍进生成节点，3/11 次编造出完整开通步骤，并在末尾伪造「参考：<企业微信管理后台-会话内容存档>」（语料中无此文）。
- **根因**：骨架只做"检索不到→改写重试"，没有"重试用尽仍无证据"的兜底；质检把"没有依据"判成 not useful，又送回改写，形成拒答→回炉→再拒答的死循环。
- **解决**：G1 生成入口零文档直接返回拒答（不调 LLM）；G1' 质检识别拒答话术直接放行；G2 引用白名单校验，全不中降级拒答、部分不中删编造行。
- **结果**：拒答 80%→100%，幻觉 17→2，P95 58.4→25.1 秒，可答题指标零下降。

### #9-#10 向量库只读错误：一个必须靠"绕过"解决的问题

- **现象**：删掉 Chroma 目录重建同路径库，或原地清空 collection 重加，都报 `readonly database`，删文件、改权限、重启都不行。
- **根因**：PersistentClient 按路径缓存连接单例，连接指向已删除的旧 inode；原地清空则撞更底层的锁。
- **解决**：新库建到临时目录 → 原子改名切换 → `os._exit(0)` 由容器 restart 拉起新进程；状态写进持久卷文件，重启后识别"刚重建完"。
- **连带坑**：数据目录自身是 bind mount 挂载点时无法 rename，必须把挂载点上移一层。

### #17 一行 glob 让重建链路静默失效

- **现象**：v2.2 上线后点"重建索引"报「未在 /app/backend/data 下找到 .md 文档」，但线上问答一切正常（因为一直在用旧库）。
- **根因**：重写时把 `glob="**/*.md"` 改成 `glob="*.md"`，pathlib 语义下不递归，而语料是按产品分目录存放的。
- **解决**：改回 `**/*.md`，容器内实测匹配 38 个文件；重建后 171→185 chunks。
- **教训**：**这类 bug 不会在"问答"路径暴露**，只有触发重建才现形——功能验收必须覆盖"重建/上传/删除"这类低频路径。

### #20-#22 实验口径：三个容易把结论带偏的细节

1. **子串比对**：答案「5 GB」vs 关键字「5GB」被判缺事实 → 加归一化复核（`eval/recheck.py`），must_contain 从 86.7% 修正为 93.3%。
2. **样本量**：拒答指标 1 题 = 6.7 个百分点，800 切块两轮跑出 80.0% / 93.3% → 单轮数字不能当结论。
3. **代理校验**：幻觉指标用"全库"判断标识符是否存在，`console.cloud.tencent.com`、`Redis`、`PPT` 这类通用词会被记成幻觉 → 报"幻觉降 60%"之前必须逐条看命中项。

### #23-#25 做完实验才知道的三个方法论坑

1. **输出话术与评分器会脱钩**。E6 给模型加了"操作步骤硬约束"，模型照做后改说「当前资料未包含具体操作步骤」，但评分器的拒答标记词表里没有这句，于是把这个**正确的拒答**判成失败（拒答率 13/15 而不是 14/15）。教训：改输出的同时要改验收标准。
2. **概念替换比整段编造更隐蔽**。问"腾讯会议能设几个联席主持人"，库里只有"指定主持人最多 10 位"，模型直接把两个概念等同，给出带出处的错答。`must_not_contain` 里写的是「最多可以设置」，而答案说的是「最多支持设置」，一字之差没拦住。这类错答比纯编造更难发现，因为它"看起来有引用"。
3. **对照实验的基线必须同源**。E3 跑分时代码里已经带了 E6 的 prompt 改动，若仍拿 E2-800 当基线，会把"prompt 加固的收益"算成"去重策略的收益"。正确做法是先重跑一次基线（E6），再比较 E3 与 E6。

### #4-#5 两个真实能力短板（E6/E4 的靶子）

- **拒答边界**：语料里"生命周期"只出现 2 次且为顺带提及，模型却输出"登录 COS 控制台 → 【存储桶列表】→ 【生命周期】→ 【创建规则】"完整路径。说明 prompt 里"不得补充资料外路径"的约束被产品常识覆盖。
- **跨产品混淆**：企业微信与微信小程序都有 `access_token`，检索层没有产品维度的信号，导致问小程序却命中企业微信文档，doc_grader 全滤后拒答。
