## 零、七条裁定

| # | 问题 | 裁定 | 一句话理由 |
|---|---|---|---|
| 1 | 三分栏还是两分栏 | **两分栏**（列表 280 + 详情 1fr） | 第三栏（调用结果）会把详情压到 550 以下，JSON 一行要 76 字符才读得顺 |
| 2 | 方法徽标 | **3px 左边框 + 等宽文字，零填充**，颜色只用 3 档（读=中性 / 写=蓝 / 删=红） | 面积从 1200px² 降到 60px²（−95%），一行 0 个彩色实底块 |
| 3 | 响应 JSON | **纸底等宽，不用 `--code-bg` 深色块** | 深色块是"代码"的语汇，响应体是"数据"；一屏 400px 高的黑块会把方法/路径的层级压掉 |
| 4 | 语法着色 | **不着色**（key `--ink` 600 / value `--ink-soft` 400 / null `--muted`） | 一色一义是硬约束；用 `--teal` 标字符串等于引入第 5 个语义 |
| 5 | `curl` 示例 | **用 `--code-bg` 深色块** | 它是"可复制的代码片段"，与问答里的代码块同类，对照第 3 条 |
| 6 | 试调用 | GET 直接发；POST/PATCH/DELETE 走 `<dialog>` 二次确认 | 这个面板能一句话删掉一个库，闸门必须在视觉层 |
| 7 | 窄屏 | 容器 < 700 → 列表变顶部 `<select>`，详情全宽；**不用抽屉** | 抽屉（`--drw-w` 420）是为"看一行数据的纵深"，这里是"切换主对象"，不该用第三级容器 |

## 一、在控制台里的位置

`#viewAdmin` 现有 4 个页签（语料索引 / 用户管理 / 权限矩阵 / 审计日志），接口面板是**第 5 个**：

```
┌──────────────────────────────────────────────────────────────────┐
│ topbar 65：腾讯云产品技术支持   [问答|知识库|控制台]              │
├──────────────────────────────────────────────────────────────────┤
│ ┌── .pane-wide  max-width 1200 · 容器 1136 ────────────────────┐  │
│ │ 语料索引  用户管理  权限矩阵  审计日志  ├ 接口 ────────────  │  │ 38+18
│ │ ┌────────────┬─────────────────────────────────────────┐   │  │
│ │ │ 左列 280   │ 右列 854（详情）                         │   │  │
│ │ └────────────┴─────────────────────────────────────────┘   │  │
│ └──────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

| 项 | 数值 | 依据 |
|---|---|---|
| 页签条 | 复用 `.drawer-tab`（14px / 6+12 padding / 激活 2px `--blue` 下划线），高 **38**，`margin-bottom` 18 | 控制台既有语汇，**不新增第 2 套 tab** |
| 面板根 | `<div id="paneApi" class="pane-wide">` | `.pane-wide` 已有：`#viewAdmin > .pane-wide { max-width: var(--content-work) }`（`app.css:1809`，锚点 `#viewAdmin > .pane-wide`）。**不要**用默认的 880 —— 880 下右列只剩 600，JSON 只有 70 字符宽 |
| 面板高 | **不写 `100vh`**。给 `#viewAdmin` 加状态类 `.is-api`：`.is-api { overflow: hidden; display: flex; flex-direction: column; }`，页签条 38+18 = 56 为 `flex: none`，`.api-split { flex: 1; min-height: 0; }` | 用 100vh 减常量会在 topbar 行高变化时错位（实测 topbar 是 **65** 而非骨架图里的 56）。父级撑满后，唯一要对的数是"面板底边距视口底 24px"。`min-height: 0` 不能漏 —— 漏了就是两栏一起滚 |
| 外框 | `1px --line` + `--r-md`，`overflow: hidden`（裁圆角） | 与 `.kbtable` 的外框同规格（后台 §3.1） |

**页签命名为「接口」，不叫「API 文档」**：叫"文档"会让用户期待 Swagger UI（可展开的 schema 树、Authorize 按钮、Try it out）；这个面板给的是"列表 + 一条路径 + 试一次"，说"文档"会持续被拿来对比。

| 区 | 值 | 理由 |
|---|---|---|
| 左列宽 | **280**（定宽，`flex: none`） | 行内最宽内容 = 60(method) + 8 + path + 8 + 22(危险标签) + 24(左右 padding) = 122 + path；280 给 path 留 **188**（mono 12 约 26 字符，按 0.6em = 7.2px/字符），够露出 `/kbs/{kb_id}/members/…` 这一层差异 |
| 右列宽 | `minmax(0, 1fr)` → **854** | 账：容器 1136 − 2（外框 `1px --line` ×2）= 1134，− 280 = 854。**分隔线用 `box-shadow: -1px 0 0 var(--line)`，不占布局** —— 若改成 `border-left` 会再吃 1px，下面整张表（662 / 602 / 746）全部要重算。必须写 `minmax(0,1fr)`，否则 JSON 里的长行会把 grid 撑破（`1fr` 的最小值是 `auto`） |
| 左右分隔 | `1px --line`，**不加阴影** | 上位原则 3 |
| 容器查询的宿主 | `#paneApi { container-type: inline-size; container-name: api }` | 挂在**版心元素**上（宽 = 1136），不是 `.api-split`。`.api-split` 自己带 `1px` 外框，量它会得 1134 —— 一档只差 2px 时看起来对，跨档就会算错。命名 `api` 是为了不与门户的 `portal` 容器互相命中 |
| 右列内边距 | 20 / 20 / 24 | 比 `--sp-4` 大一档：详情区是"纸面向内退一格"，与左列表形成层次 |
| JSON 可视宽 | 854 − 40(内距) − 32(块内距) − 36(行号槽) = **746** → mono 11px 约 **113 字符** | 113 字符能容下一个 3 层嵌套、键名 12 字符的对象行不折行 |

## 三、左列：接口列表

### 3.1 分组

按**路径第一段**分组，组的顺序按使用频率而非字母序：

| # | 组名 | 匹配 | 条数（实测） | 排序理由 |
|---|---|---|---|---|
| 1 | 对话 | `/chat*` | 3 | 最高频，几乎是唯一会"试调用"的组 |
| 2 | 知识库 | `/kbs*` | 11 | 第二个日常入口 |
| 3 | 文件 | `/files*` | 3 | 与知识库成对出现，紧跟其后 |
| 4 | 管理 | `/admin*` | 19 | 最大的一组，放在中段（天天用，但不常"试"） |
| 5 | 开放接口 | `/open/v1*` | 5 | 对外，权限最敏感，靠后 |
| 6 | 认证 | `/auth*` | 3 | 只在排障时看 |
| 7 | 诊断 | `/`、`/health` | 2 | 不属于任何前缀的 2 条孤儿路由，**不隐藏**（`/health` 是运维要的第一条），置底（组名与 UX 统一用「诊断」） |
| | **合计** | | **46** | |

> **条数不写进界面文案**（界面显示的是解析结果）。本文的 46 是 `backend/api/main.py` 本次实测值（含 `/` 与 `/health`）；`docs/openapi.json` 里那份是 v2.1 的 33 条快照，已过期，**不要拿它当基准**。验收时以运行时解析结果为准（见 §九 第 1 条）。
> 「诊断」组是本文对"按前缀分组"的一处**补充**，不是例外：`/` 与 `/health` 没有可用的前缀，不归组就会出现"点了全部却少 2 条"。

组头规格：

| 元素 | 值 |
|---|---|
| 高 | 36 |
| 底 | `--paper`（与行底 `--surface` 差一档，形成分组带） |
| 文字 | 组名 12px / 600 / `--ink-soft`，字距 `.04em`（表头语汇，后台 §3.5） |
| 计数 | `--mono` 11px / 400 / `--muted`，紧随组名 `--sp-2` |

### 3.2 行

高 **48**（`--row-h`），两行：

```
┌ 12 ─────────────────────────────────────── 12 ┐
│ │POST   /kbs/{kb_id}/upload                  │  18：method 槽 60 + path mono 12/500
│ │       Kb Upload                        计费 │  14：summary 11 muted + 危险标签 11/600 --red
└────────────────────────────────────────────────┘
```

| 元素 | 令牌 / 值 | 理由 |
|---|---|---|
| 方法槽 | 宽 **60**，`border-left: 3px solid`，`padding-left: 8`，`--mono` 11px / 600 | 60 = 3(线) + 8(内距) + 43(DELETE 6 字符 × 7.2) + 6(余量)；**定宽**才能让 46 条路径全部左对齐在同一 x |
| 方法线色 | GET → `--line-strong`；POST / PATCH → `--blue`；DELETE → `--red` | 三档 = 三个语义域（读 / 改 / 不可逆）。**PATCH 与 POST 同色**：颜色表达"会不会改状态"，方法名本身已经区分了 POST/PATCH |
| 方法字色 | 默认 `--ink-soft`；DELETE 用 `--red` | `--line-strong` 作字色只有 1.2:1，**线可以有弱色，字不能** |
| 路径 | `--mono` 12px / 500 / `--ink`，单行截断 + `title` 全路径 | 与后台编码列同字体 |
| summary | `--fs-2xs` 11px / 400 / `--muted`，单行截断 | FastAPI 自动生成的是英文函数名（`Kb Upload` / `My Kbs`）。**原样显示，不翻译** —— 见 §3.4 |
| 危险标签 | 11px / 600 / `--red`，右对齐，`margin-left: auto` | 纯文字、无底无框（沿用"授权范围 = 文字"的形态，后台 §4.4） |
| 行间线 | `1px --line`，组内最后一行不画 | 后台 §3.1 |

**路径列可用宽的账**：280 − 24(左右 padding) = 256；− 60(方法槽) = 196；− 8(间隙) = 188 → 路径 188px ≈ **26 个** mono 12 字符（0.6em = 7.2px/字符）。`/kbs/{kb_id}/files/{fid}/download`（34 字符）会截成 `/kbs/{kb_id}/files/{fid}/d…`，**这是可接受的**：同组内前缀都一样，差异在后半段，`title` 给全文。危险标签在第二行，不占路径宽度。

### 3.3 危险接口：四类，行内 + 详情各一处

| 标签 | 命中接口 | 为什么危险 |
|---|---|---|
| **计费** | `POST /chat`、`POST /chat/stream`、`POST /open/v1/chat` | 每次调用真的走 LLM，产生额度消耗；`/chat/stream` 还会占住一条 SSE 长连接 |
| **重建** | `POST /admin/rebuild`、`POST /files/{fid}/approve` | 同步触发索引重建，期间该库检索结果可能为空（问答侧会表现为"答不上来"） |
| **批量** | `POST /open/v1/users`、`POST /open/v1/users/batch` | 一次写入多个账号，部分失败不回滚 |
| **不可逆** | 全部 `DELETE`（6 条：用户 / 文档 / 库 / 文件 / 成员 / 分组授权） | 无回收站接口，删了只能重建 |

两条实现约束：

1. **标签是查表得来的，不是按方法猜的**（`DELETE` 全标"不可逆"可以规则化，但"计费/重建/批量"必须按 `(method, path)` 显式登记）。表只有一份，放在 `app.js` 常量里，附注释指回本节。
2. **同一行最多 1 个标签**。若命中两类（例如将来出现"批量 + 不可逆"），取**后果更重**的那个，顺序：不可逆 > 批量 > 重建 > 计费。

### 3.4 summary 不翻译（一条会被反复提的裁定）

`/openapi.json` 的 `summary` 是 FastAPI 从函数名自动生成的英文（`Admin Delete Kb`、`My Kbs`、`Kb Files`），不是中文业务描述。三种处理方式的代价：

| 方案 | 结果 | 判定 |
|---|---|---|
| 前端维护一张中英映射表 | 46 条起步、每次加接口都要改前端；映射表一旦落后，面板显示的就不是"接口真相" | ✗ 这是第二份真相 |
| 让后端补 `summary="中文"` | 面板自动跟着变好 | ✓ **推荐**，但属于后端改动，不在本轮 |
| 原样显示英文 | 略生硬，但永远与 `openapi.json` 一致 | ✓ 本轮采用 |

**裁定：原样显示。** 这个面板的第一价值是"人和 AI 看同一份真相"，翻译会立刻制造第二份。中文只出现在**导航性文案**里（组名、危险标签、段标题、按钮），不出现"接口说明"里。

### 3.5 左列顶部：筛选

- 容器高 **56**（`padding: 12` + 32 输入 + `1px --line` 底）；输入框复用 `.wsearch`（32 高 / `--fs-sm` / `--line-strong` 边），宽 100%。
- 占位符「筛选路径或 summary（按 / 聚焦）」；子串匹配 path 与 summary，不区分大小写。
- 命中时组头计数变"命中/总数"，无命中的组整组收起（**不删**，保留位置，清空后回到原位）。
- 有值时右侧出现 `✕`（16px `--muted`，`aria-label="清除筛选"`）；无结果显示 13px `--muted`「没有匹配的接口」+ 文字动作「清除」（12/600 `--blue`）。

## 四、右列：详情

### 4.1 页头（72px）

```
POST  /kbs/{kb_id}/upload                          [复制 curl]  [试调用]
Kb Upload · 管理员 · 3 个参数
──────────────────────────────────────────────────────────────────────
```

| 元素 | 值 | 理由 |
|---|---|---|
| 高 | 72（`padding: 14 0 14` + 两行 22 + 4 + 16） | 与后台详情页页头（面包屑 + 标题 + 副行）同构，但去掉面包屑：这里没有上一层对象 |
| 方法徽标 | 同 §3.2，但方法槽宽 **72**（3 + 10 + 40 + 19），字 12px | 详情页是主对象，可大一档 |
| 路径 | `--mono` `--fs-md` 15px / 600 / `--ink`，`overflow-wrap: anywhere` | 路径是本页最重要的一行，比列表大 3px；长路径必须能断行（不截断 —— 详情页截断就没意义了） |
| 副行 | 12px：`summary`（`--muted`）· **权限文字** · `N 个参数`（`--muted`） | 权限是**逐接口不同**的维度，不能写一句"需要 Bearer"糊过去（见下表） |
| 右侧控件 | 最多 2 个：`复制 curl`（ghost 36）+ `试调用`（主按钮 36，`--blue`） | 后台 §2.4：页头控件 ≤3，主操作恒 1 个。这里唯一的主操作是"试调用" |
| 底线 | `1px --line`，页头下 20px 起第一段（详情页唯一一条结构线） | 不加第二条：下面 5 段靠 24px 留白分 |

> **权限文字必须逐接口写，且只用文字不用徽标**（第五个维度不能再给一个色块）。五档：
>
> | 档 | 文字 | 字色 | 判定 |
> |---|---|---|---|
> | 公开 | `公开` | `--muted` | `/`、`/health`、`/auth/register`、`/auth/login` |
> | 登录 | `登录` | `--ink-soft` | 其余 `Depends(get_current_user)` 的接口 |
> | 管理员 | `管理员` | `--ink-soft` / 600 | `/admin/*`（除下一档） |
> | 仅超管 | `仅超级管理员` | `--ink-soft` / 600 | `/admin/search`（`require_super_user`，全表唯一） |
> | API-Key | `API-Key` | `--amber` | `/open/v1/*`（`require_api_key`） |
>
> **为什么不能用 openapi 推断**：`main.py` 全部用 `Depends(get_current_user)` 而不是 `Security(HTTPBearer())`，所以 `components.securitySchemes` 为空、`security` 字段也不存在。这张表必须**照 `security.py` 手写**，不能从契约读。琥珀只给 `API-Key` 一档：它在「等一等」的语义域里（缺凭证，不是没权限）。

### 4.2 段标题（详情页统一）

`--fs-xs` 12px / 600 / `--ink-soft`，字距 `.04em`；下距 8，段间距 24（`--sp-6`）；**无竖条、无编号**（5 个段各挂一条竖条会读成"5 个待办"）。

与 `.kbtable th` 同规格的理由：详情页 70% 内容是一张表 + 一块 JSON，段标题应服从表头语汇，而不是抢衬线标题的位置（本页衬线标题只有路径那一行）。

### 4.3 参数表（5 列定宽）

`border-box` 计算，宽度**已含左右各 12px 内边距**，可直接写进 `<colgroup>`：

| # | 列 | width | 内容 | 理由（为什么够） |
|---|---|---|---|---|
| 1 | 参数名 | **200** | `--mono` 12px / 500，超长截断 + `title` | 最长实测字段名 `display_name`（12 字符 × 7.2 = 86）+ 24 padding = 110；按 **24 字符**上限留：24×7.2 = 173 + 24 = **197 ≤ 200** |
| 2 | 位置 | **72** | 12px `--muted`：`path` / `query` / `body` / `header` | 最长 `header`（6 字符，40px）+ 24 = 64 ≤ 72，余 8 |
| 3 | 类型 | **96** | `--mono` 11px / 400 | `integer`（46）+24 = 70；**类型只显示基类型**（`array` / `object`），元素类型进 `title`，否则 `array<string>` 需要 110 > 96 |
| 4 | 必填 | **56** | 12px：`必填` / `—` | `必填` 24px + 24 padding = 48 ≤ 56；不写"是/否"（"否"要读两遍才知道是"不必填"） |
| 5 | 说明 | `auto`，`min-width: 160` | 12px `--muted`，可换行（唯一允许换行的列） | 814 − (200+72+96+56) = **390** 实得，远大于 160；160 只是窄屏兜底下限 |

| 表规格 | 值 |
|---|---|
| 表头高 | 40（`--th-h`），底 `--paper-2`，`sticky top: 0`，**唯一深线** `1px --line-strong` |
| 行高 | 40（参数没有次字段，用紧凑档；后台 §3.4） |
| 行线 | `1px --line`，最后一行不画 |
| 竖线 | **0 条**（后台 §7 陷阱 1） |
| 空表 | `path` 参数都没有的接口 → **不画表**，只写一行 12px `--muted`「该接口无参数」。空表头 40 + 0 行看起来像加载失败 |
| 未声明 | 接口用 `Request` 直取 query（`/admin/search?q=` 这类部分声明了，`/kbs/{id}/files` 的 `status` 没声明）→ 表下一行 12px `--muted`「`openapi.json` 只声明了 path 参数；query 参数在 handler 内直取，未声明」 | 

**窄屏只收第 1 列，其余四列不动**：位置 72 / 类型 96 / 必填 56 都是"刚好装下最长值"，再收就开始截字；只有参数名是长尾（多数 ≤ 12 字符），收它最不疼。

| 容器档 | 参数名 | 位置 | 类型 | 必填 | 说明实得 |
|---|---|---|---|---|---|
| ≥ 860 | 200 | 72 | 96 | 56 | **390**（表宽 814 = 右列 854 − 40，− 424） |
| ≤ 859 | **150** | 72 | 96 | 56 | **188**（表宽 562 = 右列 602 − 40，− 374） |
| ≤ 699（单列） | **120** | 72 | 96 | 56 | **278**（表宽 622 = 右列 662 − 40，− 344） |

150 时 `display_name` 仍完整（86 + 24 = 110 ≤ 150）；120 时它刚好卡住（110 ≤ 120），再长的字段名才截断 —— 而实测最长的就是它。

**为什么不用可展开的 schema 树**：`$ref` 展开需要递归渲染 `components.schemas`（本产品有 10 个 schema，含 `HTTPValidationError` 这种噪音）。展开树会让详情页变成 Swagger，与"一屏能读完一个接口"的目标冲突。JSON 请求体示例已经把字段结构说清楚了。

### 4.4 请求体示例

| 情况 | 渲染 |
|---|---|
| 有 `requestBody` + `$ref` schema | 按 schema 生成示例：字段名取 schema property，值按类型占位（`string`→`""`、`integer`→`0`、`boolean`→`false`、`array`→`[]`、`object`→`{}`），2 空格缩进 |
| 有 `requestBody` 但 schema 为空 `{}` | 一行 12px `--muted`「`openapi.json` 未声明该请求体的 schema（handler 直接读 `Request`）」+ 一句「结构只能从「试调用」的报错里反推」 |
| 无 `requestBody` | 一行 12px `--muted`「该接口无请求体」 |

**禁止编造字段值**：示例里的值必须是"类型占位"，不能写 `"财务制度库"` 这种看起来像真实数据的字符串 —— 面板是真相视图，示例一旦像真数据就会被当成默认值复制走。

### 4.5 试调用

**分档（按方法，不按人）**：

| 方法 | 交互 | 按钮规格 |
|---|---|---|
| GET | 点一次直接发 | ghost 36 |
| POST / PATCH | 弹 `<dialog>` 确认（复用后台 §10.3 危险确认弹窗规格） | 主按钮 36 `--blue` |
| DELETE | 同上，但主按钮用 `--red`（hover `--red-dk`） | 主按钮 36 `--red` |
| **不可试（能力缺失）** | `POST /chat/stream`（半边流式会误导）、下载类（触发浏览器下载）、两个 `upload`（`multipart` 无法在面板里选文件）、`/open/v1/*`（需服务端 `X-API-Key`）、非超管身份下的 `/admin/search` | 按钮 `opacity: .45` + `not-allowed` + `title` 写原因（「需要服务端 API-Key，浏览器不持有」/「仅超级管理员」），**不隐藏**（隐藏会让人以为接口不存在） |

确认弹窗正文（三段，缺一不可）：

1. 标题**按后果分类，不能统一写"会真的改数据"**（`POST /chat` 不写业务数据，花的是额度）：

| 类别 | 标题 | `requireText` |
|---|---|---|
| 计费 | `试调用会消耗 LLM 额度` | 无 |
| 重建 | `试调用会触发索引重建` | 无 |
| 批量 | `试调用会一次写入多个账号` | 无 |
| 不可逆 · 重 | `试调用会删除数据，且无法恢复` | **输入 `DELETE`** |
| 不可逆 · 轻 | `试调用会移除一条授权` | 无 |

2. 一行代码：`DELETE /files/42`（`--mono` 13 / `--ink`）。
3. 后果条：40px 高，`--red-bg` 底 + 左 3px `--red` + **文字 `--ink` 14px / 500**，前缀「需二次确认」`--red` 14/600。

**`requireText` 只给 4 个真正不可恢复的**：`DELETE /admin/kbs/{id}`、`DELETE /files/{fid}`、`DELETE /admin/documents/{name}`、`DELETE /admin/users/{username}`。`DELETE /kbs/{id}/members/{u}` 与 `DELETE /kbs/{id}/groups/{g}` **不加** —— 它们能重新授予，加输入框是把"可恢复"说成"不可恢复"。
需要输入的那种，弹窗内多一行输入框：宽 100%、高 32、`--mono` 13、占位符 `输入 DELETE 确认`；未精确匹配时主按钮 `opacity: .45` 且禁用，**匹配后才变 `--red` 可点**。

> 后果条文字**不能**用 13px `--red` on `--red-bg` —— 那只有 4.3:1，上位文档已明确"朱砂不能做浅底小字，只允许 ≥14px 半粗"。这是最容易复制错的一条。

**参数输入区**（在「试调用」段内，用两列定义列表，不用表格）：

- 路径 / query 参数行：标签（参数名 mono 12 / 160 宽）+ 输入框（32 高，`flex: 1`，`.wsearch` 规格）；query 占位符写默认值（`limit=50`）。
- body：`<textarea>` 预填 §4.4 示例，`--mono` 12，`min-height: 96`、`max-height: 200` 超出滚动（上位 §五）。
- 必填项未填：按钮 `opacity: .45` + `not-allowed` + `title="请先填写 kb_id"`，**保留边框**（上位 §五：占位不跳动）。
- 执行中：文字换「调用中…」并禁用，**不转圈**（上位 §五）。

### 4.6 响应区

```
200 · 128ms
┌────────────────────────────────────────────────┐
│ 1 │ {                                           │  行号槽 36，`--paper-2` 底，右对齐 mono 11 `--muted`
│ 2 │   "id": 42,                                 │  key `--ink` 600
│ 3 │   "name": "",                               │  value `--ink-soft` 400
│ 4 │   "status": null                            │  null / 空数组/空串 `--muted`
└────────────────────────────────────────────────┘
```

| 元素 | 值 | 理由 |
|---|---|---|
| 状态行 | `--mono` 12px：`200 · 128ms`；非 2xx 时状态码 `--red` | 耗时必须有 —— 判断"是不是超时"的第一依据 |
| 块容器 | 底 `--surface`，边 `1px --line`，`--r-sm`，`padding: 12 0 12 0`，行号槽 36 | 与"表格外框"同级，不是代码块 |
| 行号槽 | 宽 36，底 `--paper-2`，右对齐，`--mono` 11px / `--muted`，`user-select: none` | 36 = 3 位数（999 行）+ 左右 8；超过 999 行时按需加宽，不加挡 |
| 正文 | `--mono` 11px / 行高 1.65（17.9 ≈ 18），`white-space: pre` | 11px 是 JSON 的扫描尺寸；12px 会让 113 字符的预算降到 103 |
| 折叠 | 超过 **40 行**折叠为前 20 行 + 「展开全部（N 行）」文字动作 | 40 行 ≈ 720px，已超一屏；不折叠会让"回到页头"要滚 3 屏 |
| 非 2xx | 块边 → `1px --red`，状态行 `--red`；**不整块红底** | 红底 + 红字只有 4.3:1，且 600px 宽的红块会把错误信息本身淹掉 |
| 未调用 | 32px `hint-bar`：`· 还没有调用记录 · 点右上「试调用」` | 与后台 §5.2 的轻提示同规格，不用 64px 空态块 |
| 失败（网络断） | 13px `--red` 一行「请求未送达（网络错误），接口没有被调用」+ 「重试」 | 必须说清"到底有没有执行" —— 这是试调用面板最容易伤人信任的地方 |

**为什么响应不用 `--code-bg`（三条理由，按重要性）**：

1. **语汇冲突**：`--code-bg` 在本系统里只出现在"可复制的代码片段"（问答回答里的 ``` 块、这里的 curl 示例）。响应 JSON 是**数据**，不是用户要复制的代码。两者用同一种黑块，等于告诉用户"这也是一段代码"。
2. **层级反转**：一块 600×400 的 `#2B2B26` 在 `#F6F4EE` 页面上是页面里最重的元素，而本页真正的主对象是「方法 + 路径」。黑块会把页头的视觉权重直接压到第二。
3. **扫读效率**：JSON 的阅读动作是"找 key"，纸底上 key 加粗 600、value 常规 400 的对比，比反白块里的全同色文本更快；反白块里想强调 key 就得加色，而加色破一色一义。

### 4.7 复制 curl

- 按钮：ghost 36，文字「复制 curl」；成功后 1.6s 内变「已复制」（`--teal`，不弹 toast）。
- 内容：`curl -X POST '<origin><path>' -H 'Authorization: Bearer <当前 JWT>' -H 'Content-Type: application/json' -d '{…}'`。
- **不在页面上铺代码块**：curl 里带 token，铺出来会被截图带走。想看内容时点「查看」→ `<dialog>` 内 `--code-bg` + `--code-ink` 展示（此时它确实是"一段代码"，深色块用得对）。
- `title` 必须写「含你的登录凭证，请勿分享」；按钮文案里**不写**这句，避免它被读成"这个按钮很危险"。

## 五、状态四态

### 5.1 列表行

| 态 | 表现 | 值 |
|---|---|---|
| 默认 | 底 `--surface`，行间 `1px --line` | — |
| 悬停 | 底 `--paper`，路径 `--ink` 不变 | 与表格行 hover 同（后台 §3.6） |
| 选中（当前打开的接口） | 底 `--blue-bg` + 路径字重 400 → **600** | **不加左侧竖条**：方法槽已经有 3px 左边框，行首再加一条会变成双线；这里用"底色 + 字重"双通道代替，色差（`--surface` → `--blue-bg`）在单列列表里不会被列线切碎，不会误读为 hover |
| 焦点 | `outline: 2px solid var(--blue); outline-offset: -2px` | 与表格行同（后台 §3.6） |
| 禁用 | 行**不置灰、不禁点**；`/open/v1/*` 与「仅超管」两条在行尾多一个 `锁` 字符（12px `--amber`） | 按后台 §3.12：这是 **forbidden/locked**，不是 disabled —— 要画出来，但要说清钥匙在哪。**不能**"先让他点、再报 403"：那会把"缺服务端密钥"报成"接口坏了"（`/open/v1/*` 浏览器永远拿不到 `X-API-Key`） |

### 5.2 试调用按钮

默认 `--blue` / `#FFF` / 36 高 / `--r-md`；悬停 `--blue-dk`（DELETE 场景 `--red` → `--red-dk`）；聚焦 `outline: 2px solid var(--blue); outline-offset: 2px`；无"选中"态（一次性动作）；禁用 `opacity: .45` + `not-allowed` + `title` 写原因（「请先填写 kb_id」/「调用中」），**保留边框**。

### 5.3 段级

- **加载**（首次解析）：左列 6 行骨架（48 高，路径条 60%、summary 条 40%，`--skel-bg`），右列 3 段骨架，150ms 后出现（后台 §5.1）。
- **空**（未选接口）：右列垂直居中 —— `▤` 36px `--line-strong` + 16 + 「从左边选一个接口」16 衬线 + 8 + 「共 N 个，按路径前缀分组」13 `--muted`。宽屏有列表就不该出现切换器。
- **错误（三档，各占且只占一个按钮位）**：`/openapi.json` 自 v2.2 起要求登录（`main.py:38` 的 `gate_schema` 中间件只调 `get_current_user`，所以**今天契约请求实际只会是 401**；403 是将来给契约加角色限制才会出现的档，现在就得写好，免得那天临时拼）。失败必须先看状态码再决定给什么按钮。三档的按钮位**互斥**，任何一档都只有 0 或 1 个动作：

| 状态 | 文案（`13px --red`，同一行） | 动作 | 为什么 |
|---|---|---|---|
| **401** | 「登录已过期，接口清单需要登录后读取」 | **「重新登录」**（12/600 `--blue`，跳登录、不刷面板） | 身份没了，换一个身份能好；刷新页面不会 |
| **403** | 「当前账号无权查看接口清单，请联系系统管理员」 | **零按钮** | 身份不够，重登一百次还是 403；**「重试」同样无效** —— 换动作也换不出东西，只能换人 |
| **5xx / 网络 / 非 JSON** | 「读取接口清单失败（HTTP 500），接口清单不可用」 | **「重试」**（同规格） | 服务端或链路抖了，再发一次可能就好 |

> 判据（ux-designer-2 给的，本页三档都由它推出）：**用户自己再点一次，这件事会不会变好？** 会 → 「重试」；不会 → 换动作；换动作也没用 → **不给按钮，只给下一步找谁**。

> **同一动作在多处渲染，必须共用一个容器类**：错误动作现在有两个落点 —— 整页错误块（`.api-err-act`，首屏加载失败）与顶部错误带（已有清单、刷新失败）。两者共用同一个渲染函数，所以**容器类必须一致**，否则"按钮该不该在这儿"既没法验、也没法统一改。给错误带里那个动作也套 `.api-err-act`（现在它裸插在 `.api-errbar` 里，是唯一一处例外）。断言写 `.api-err-act button`，**不要写 `.api-meta button`** —— 页头 meta 条里有「刷新契约」（`#apiRefresh`），那是 chrome 不是错误动作，混在一起会让"零按钮"这条永远失败；一条永远失败的验收比没有验收更糟。

> **容器类只负责"能查到"，不负责"长得对"**。`.api-err-act` 现在自带 `margin-top: var(--sp-4)`（16px，`app.css:2397`），那是给整页错误块写的。直接套进 `.api-errbar`（`display: flex; align-items: center`，一行）会把它当外边距算进 flex 行高 —— 条整体高 16、按钮下移、不再与左侧文案居中对齐，**不报错、只是歪**。这是最容易被放过的一类。
>
> 修法不是"再加一条覆盖"，而是**让间距归父级**：
>
> ```css
> .api-err-act { margin-top: 0; }                       /* 默认不带间距 */
> .api-errblk .api-err-act { margin-top: var(--sp-4); } /* 整页错误块才需要 */
> .api-errbar .api-err-act { flex: none; }              /* 错误带里不被压缩 */
> ```
>
> 理由：一个可复用的容器类不该自带只对某个父级成立的间距，否则第三个落点还要再写一次覆盖 —— 覆盖越积越多，最后没人敢动。
>
> **空容器也要收掉**：403 是零按钮，但 `<div class="api-err-act">` 仍会被渲染成空壳。即使 margin 归零，它在 `.api-errbar` 的 `gap: 12` 里仍占一格。首选**渲染层不输出容器**（有动作才拼 `.api-err-act` 那层 HTML，没有就返回空串），`:empty` 只当兜底 —— 因为 **`:empty` 对空白字符敏感**：模板里留一个换行或空格，它就不匹配，兜底会静默失效。用 `:empty` 就必须做到"这个 div 里一个字符都没有"。
>
> 高度账（`--btn-h-sm` 32 / 文案行高 18 / `padding: 8` / 边框 1×2）：

| 场景 | `.api-errbar` 高 | 拆解 |
|---|---|---|
| 401（1 按钮） | **50** | 32 + 16 + 2 |
| 403（0 按钮） | **36** | 18 + 16 + 2 |
| 若 16px 漏进 flex | 66 / 52 | 各多 16 —— 这两个数一出现就是 margin 没归零 |

- 三档都保持：左列趋空、右列保留空态文案（**不许**把左列画成"0 个接口"—— 那是在说"这套系统没有接口"，把可用性事故说成了事实）。**403 尤其不能画成空列表**：那会让人以为自己权限被降到"一个接口都没有"，而事实是这套清单他没资格看。
- **部分成功**：解析出 M 个非 5 种方法之外的操作 → 底部 32px `hint-bar`「已忽略 M 个非标准方法」。**不静默丢弃**（静默丢弃等于让"共 N 个"说谎）。

## 六、权限与可达性

- **面板可见性**：只有 `admin` 能看到「接口」页签 —— 复用 `#navAdmin` 的可见判定（`hidden` 属性），**不新写第二套角色判断**。
- **员工**：完全看不到页签；hash 直达 `#admin/api` 落到 `#chat`（与现有 admin 分发同一逻辑）。
- **数据可见性**：面板列的是"接口存在性"，不是"你能调用的接口"。普通用户即使看到也会在调用时 403 —— 所以"隐藏"是导航层的事，不是安全层的事。
- **`GET /api/openapi.json` 本身**：v2.2 已收口 —— `main.py:22` 的 `FastAPI(docs_url=None, redoc_url=None)` 关掉了自带的两个页面，`gate_schema` 中间件（`main.py:38`）对 `/openapi.json`、`/docs`、`/redoc` 三条路径统一要求登录。**本文 v1.0 写的"未登录可枚举"已不成立**，面板可以直接按"登录后才拿得到"设计。定性上是"**契约不给没登录的人看**"，不是"契约本身需要身份"—— 后者会让人以为 `/openapi.json` 是个业务接口，前者才是这层中间件的真实语义。
- **由此多出一条行为**：JWT 过期时这个请求会 401，面板必须落到 §5.3 的 401 分支（给「重新登录」，不给「重试」）。这是"接口面板自己也会过期"的唯一表现，不要漏。

## 八、唯一允许横滚的地方：窄屏 JSON

- **授予对象**：**仅**「响应 JSON 块」，**仅**容器 < 700 时。
- **理由**：38 字符宽里折行的 JSON 读不出结构 —— 折出来的续行会和下一行的 key 混在一起（`"a": [1,2,` / `3]` 被读成两个字段）。横滚至少保住"一行 = 一条数据"。代价是触屏上要单指横扫，且 8px 滚动条吃宽。
- **边界**：参数表、请求体示例、页头、列表**一律不横滚**；请求体示例在窄屏用 `pre-wrap; word-break: break-all`（它比响应短，可以换行）。实现上只给 JSON 的直接容器 `overflow-x: auto`，**不能**给 `.pane-wide` 或面板根加 —— 那会让整页横滚，正是后台 §3.1 否决的"没做完的表格"。
- **与后台 §3.1 的关系**：该节说"除分组授权矩阵外任何表格不得横滚"。本条是**能力级例外**，按后台 §3.8 的分级，授予处（本节）写"唯一"，别处只写"见 §八"。

  |---|---|---|---|

  | ② | `.api-err-act` 宽 = **0** | 空壳没删（空 div 在 `gap: 12` 里白占一格） | 两个位置 |
  | ③ | `.api-errbar` 高 = **36**，且 `getComputedStyle(.api-errbar .api-err-act).marginTop` = `0px` | 间距没归位 | **只在错误带** |

  **第 ③ 步不能套到整页错误块上**：`.api-errblk` 复用 `.api-blank`（`display:flex; justify-content:center; min-height: 260px; height: 100%`），它的高度由右栏撑满 —— 在它上面量会稳定得到 260+，那不是 bug，是一条永远失败的验收。

  > **通则：只有跟视口无关的数才配当断言。** `.api-blank` 是 `min-height: 260` **加** `height: 100%` —— 换一次窗口它就变一次，它不是"不好测"，是**它本身不是常量**。而错误带的高度只由 `padding + 行高/按钮 + 边框` 决定，50 / 36 / 66 / 52 在任何窗口下都成立。**自检：看到"量某容器高度"的验收，先问它是不是 `100%` 的。**

  **为什么 ③ 必须同时有"高 36"和"marginTop = 0px"** —— 高度断言有两个失效方向，只堵一个不够：

  | 失效方向 | 怎么发生 | 后果 |
  |---|---|---|
  | **假阳性** | 403 误渲染按钮，条高 **50** —— 而 50 恰好是 **401 的正确值** | 「高度正常」被误读，以为这条是 401 场景 |
  | **不完备** | 那 16px 被负 margin、行高变化或按钮改版**部分抵消**，高度仍是 36 | 间距根本没归父级，但高度看不出 |

  > **根源：和值不能反推加数**（ux-designer-2 补的施工落点）：高度是**多个因子的和**（`padding` + 行高或按钮 + 边框 + 混进来的 `margin`），`marginTop` 是**单个加数** —— 3 + 5 与 4 + 4 都是 8。所以"量总高"与"量某个 margin"测的是**不同粒度**，不是同一件事的两次测量；**前者天然不携带分量信息**。
  >
  > **施工动作**：用和值做断言时，必须能说出"**哪些加数可能变**"。说不出，就说明这条断言现在靠的是运气。

  所以 `marginTop` 不是"再加一道保险"，而是**高度的必要条件**：高度只回答"最后多高了"，`marginTop` 只回答"这个容器自己带不带间距"。一条失效时另一条**不会替它说话** —— 这也是为什么不能只留高度（"反正有保险"会让人放心删掉 `marginTop`，然后在下一次改按钮高度时出事）。反例数值：16px 漏进 flex 时 401 变 **66**、403 变 **52**。
