- **矩阵**：改格即生效 + 失败回滚 `updateCellDom`；撤销条 amber、10s（`UNDO_MS` 口径，倒计时 10→1，≤3s 字重 600）、撤销=反向请求、只保留最近一次；≥20 人的组在改角色/新增授权前弹确认（amber 首行「本次改动影响 N 人 / 该组 N 人将立即获得访问权」）；未分组列不可授权。
- **编辑表单**：与新建共用骨架；编码只读 + hint「编码创建后不可修改」（后端白名单本就不含 code，前端直接不给改）。

## 五、最容易出错、需要人工验证的 3 处

1. **创建者识别依赖 `GET /kbs` 返回 `created_by`**。成员表"创建者"来源列与双禁用、成员表 hint-bar 文案都读 `kb.created_by`（SQL 是 `SELECT k.*`，理论上带）。请用真实账号验证：创建者行两个操作都灰、`title` 正确；若接口实际不返回该字段，这两处会静默退化为普通 kb_admin 行（不报错、但防错档位失效）——那种情况需要把 `created_by` 加进 `list_kbs` 的返回。
2. **返回列表还原筛选/页码/滚动**：需要 >20 个库的真实数据。进详情 → 浏览器返回/面包屑，验证筛选词、页码、滚动位置三项都回来；`scrollMem` 的 key 是「筛选+页码+size」，改筛选后再返回是**有意**不还原滚动的。
3. **矩阵双冻结在真实数据量下的表现**：列多到横向滚动 + 行多到纵向滚动时，表头吸顶、首列吸左、左上角交叉格三者同时成立；以及 `max-height: calc(100vh - 220px)` 在小屏（如 768 高）上会不会把表格压得过矮。若 220px 余量不合适，只需要调这一个值。

## 五、实现细节补充（fe-engineer 补交，主理人汇编）

### 5.1 返回列表还原的三键机制
| 状态 | 存哪 | 说明 |
|---|---|---|
| 筛选 + 页码 + size | **URL hash**：`#kb?q=&dept=&level=&status=&page=&size=` | `q` 用 `replaceState`（防每次按键堆历史），其余用 `pushState`；`size` 仅在偏离默认值时写入 |
| 滚动位置 | 内存 `Map<listKey(), scrollTop>` | 进详情前 `saveListScroll()`，返回时 `requestAnimationFrame` 落位 |
| 行焦点 | `kbState.focusRowId` | 返回后渲染完把焦点还给该 `tr` |

刻意取舍：换筛选后不还原滚动（key 变了，落点是新列表首屏）；排序字段/方向不进 URL（个人偏好非共享视图），刷新回默认编码↑。

### 5.2 权限矩阵撤销条结构
```js
let mxUndo = null;   // { kbId, grp, oldRole } 只保留最近一次，不做操作栈
let mxTimer = 0;     // 同一格再次修改时 clearInterval 重置 10s 计时
```
撤销 = 反向请求：`oldRole` 有值则 POST 授权，否则 DELETE 收回；成功后局部 `updateCellDom()` 不整表重绘。撤销失败 → toast「撤销失败：该授权已被他人修改，请刷新查看」+ 整表刷新。

### 5.3 收列的已知限制
`<colgroup>` 写在 `index.html` 是静态的，收列只靠 `@container` 隐藏单元格（沿用既有做法），切档时不重建 colgroup。因此「`<col>` 数 = `<th>` 数」这条验收项**只在全列档成立**——Chromium 实测未出现列错位，但逐档严格对齐需补 `ResizeObserver` 重建 colgroup（约 10 行），未实现。

### 5.4 两个不能回退的坑
1. **不要恢复 `.no-check` 模式**：元素级 `display:none` 配 11 列 colgroup 会让后续所有列左移一格，主字段列掉进 0 宽坑（本轮实测踩过）。
2. **验收必须 Ctrl+F5**：版本号未变而内容大改时，浏览器启发式缓存会给你旧 CSS/JS，看起来像样式回归。

### 6.1 改了什么

1. **`fileActsHTML`（app.js）**：预览/下载判据从 `!pending` 改为 `canRead = 已入库 || 库管理员 || 上传者本人`，与后端 `kb_download` 的放行规则逐字对应。旧判据的漏洞：`rejected` 不是 `pending`，普通成员会在「已驳回」行看到一个**点了必 403 的下载按钮**。
2. **所有行内按钮补 `aria-label`**（`审批/预览/下载/删除 + 文件名`）——同一张表里"有的行有下载、有的行没有"，上传人在文件名次行可见（`v1 · 大小 · 上传人 · 分块 · 时间`），两种情况的行语义都完整。
3. **后端 `GET /kbs/{kb_id}/files` 可见性放宽**：非库管成员从「仅已入库」改为「已入库 + 自己上传的」。这是本轮的真发现——B6 放行了「上传者下载自己未入库文件」，但列表接口根本不把待审批文件返回给上传者，**那个矩阵格子是走不到的死代码**（第 7 个不可达态，同源问题）。修完后「编辑传完文件，列表里能看到自己的待审批行」。
