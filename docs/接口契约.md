# 接口契约 · 技术支持知识库 v2.4

> 本文档面向接入方与评审：每个接口给出**路径、权限、请求、真实响应、错误码**。
> 所有示例响应均取自线上实例（`<host>:8080`）的实际返回，非手写示意。
>
> 自动生成的机器可读版本：`GET /api/openapi.json`，交互式调试：`GET /api/docs`（Swagger UI）。

---

## 1. 通用约定

| 项 | 值 |
|---|---|
| Base URL（线上） | `http://<host>:8080/api` |
| Base URL（本地） | `http://127.0.0.1:8080/api` |
| 编码 | 请求与响应均为 UTF-8；`Content-Type: application/json`（上传接口为 `multipart/form-data`） |
| 时间字段 | Unix 时间戳（秒，浮点），如 `1793222238.0066695` |
| 鉴权 | `Authorization: Bearer <token>`，token 由 `/auth/login` 下发 |

### 1.1 鉴权与角色

系统有三层身份：

| 层 | 取值 | 作用 |
|---|---|---|
| 系统角色 `role` | `superadmin` / `admin` / `user` | 决定能否进入管理接口 |
| 库内角色 `my_role` | `super` / `kb_admin` / `editor` / `viewer` | 决定对该知识库的读写权限 |
| 账号状态 `status` | `pending` / `active` / `disabled` | 注册后需管理员审批，`pending` 无法登录 |

权限依赖：

| 依赖 | 允许的角色 | 覆盖接口 |
|---|---|---|
| `get_current_user` | 任意已登录用户 | `/auth/me`、`/chat`、`/kbs`、库内文件与成员 |
| `require_admin_user` | `admin`、`superadmin` | 全部 `/admin/*`（除下方一条） |
| `require_super_user` | 仅 `superadmin` | `GET /admin/search`（跨库原始检索，用于排障） |

### 1.2 通用错误格式

FastAPI 标准错误体：

```json
{ "detail": "具体原因" }
```

参数校验失败（422）时 `detail` 是数组：

```json
{
  "detail": [{
    "type": "string_too_short",
    "loc": ["body", "question"],
    "msg": "String should have at least 1 character",
    "input": "",
    "ctx": { "min_length": 1 }
  }]
}
```

### 1.3 错误码总表

| 码 | 含义 | 典型场景（线上真实文案） |
|---|---|---|
| 400 | 请求可解析但业务不通过 | `不支持的文件类型 .xls（仅 md/txt/pdf/docx/xlsx/pptx）`、`该文件抽取后为空（0 字符）`、`缺少查询 q` |
| 401 | 未登录 / token 无效或过期 | 缺失或伪造 `Authorization` 头 |
| 403 | 已登录但越权 | `需要知识库管理员权限`、`无权访问该知识库`、`文件未通过审批` |
| 404 | 资源不存在 | `知识库不存在`、`文件不存在`、`用户不存在`、`成员不存在或为库管理员` |
| 422 | 请求体结构不合法 | 缺必填字段、字段类型不符、空字符串 |
| 500 | 服务端异常 | `解析失败 <异常类型>: <信息>`（文档损坏或被加密） |

> **注意**：空 `question` 返回的是 **422 而非 400**——它在 Pydantic 层就被拦下了，不会进业务逻辑。接入方做重试判断时不要假设 400。

## 2. 认证

### 2.1 `POST /auth/register` — 注册（进入待审批）

| 项 | 说明 |
|---|---|
| 权限 | 无需登录 |
| 请求 | `{ "username": "zhangsan", "password": "至少 6 位", "display_name": "张三" }` |
| 响应 200 | `{ "ok": true, "status": "pending" }` |
| 关键行为 | 新账号 `status=pending`，**无法登录**，需管理员在 `/admin/users/{username}/approve` 审批 |

### 2.2 `POST /auth/login` — 登录

请求：

```json
{ "username": "admin", "password": "********" }
```

响应 200（真实返回，token 已截断）：

```json
{
  "user": {
    "id": 1, "username": "admin", "display_name": "管理员",
    "role": "superadmin", "status": "active",
    "created_at": 1793222238.0066695, "last_login_at": 1793344739.88131
  },
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhZG1pbi..."
}
```

> ⚠️ 字段名是 **`token`**，不是 `access_token`。这是接入方最容易踩的坑。

错误：

| 码 | 场景 |
|---|---|
| 400 | 用户名或密码错误 |
| 403 | 账号 `pending`（未审批）或 `disabled`（已禁用） |

### 2.3 `GET /auth/me` — 当前身份

需要 `Authorization` 头。返回 `user` 对象本身（结构同登录响应中的 `user`），不含 token。

## 3. 问答（核心接口）

### 3.1 `POST /chat` — 知识库问答

这是整个系统的入口。内部执行 LangGraph 自适应流程：
`route → rewrite → retrieve → grade_documents → generate`，质检不过则回到 `rewrite` 或 `generate` 重试（最多各 1 次）。

请求：

```json
{ "question": "对象存储的存储桶怎么删除？", "session_id": "可选，缺省自动生成" }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 至少 1 字符；空串返回 422 |
| `session_id` | string\|null | 否 | 同一 session 内保留多轮上下文，服务端按 `用户名:session_id` 隔离 |

响应 200（真实返回，`answer` 截断）：

```json
{
  "session_id": "probe-contract",
  "answer": "当前资料未包含删除存储桶的具体操作步骤。\n\n根据【资料 1】，仅描述了创建存储桶的流程...\n\n参考：对象存储控制台快速入门_腾讯云",
  "sources": [
    {
      "source": "对象存储 控制台快速入门_腾讯云_5ae2ad3a65.md",
      "path": "/app/backend/data/腾讯云对象存储/对象存储 控制台快速入门_腾讯云_5ae2ad3a65.md",
      "kb_id": "default",
      "preview": "对象存储 > 快速入门 > 控制台快速入门 ... 步骤4：创建存储桶"
    }
  ],
  "steps": ["route", "rewrite", "retrieve", "grade_documents", "generate"],
  "trace": [
    { "node": "route", "ms": 604, "note": "vectorstore" },
    { "node": "rewrite", "ms": 484, "note": "腾讯云对象存储如何删除存储桶？" }
  ],
  "route": "vectorstore"
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `answer` | 最终答案。**末尾的「参考：」行已过引用白名单校验**，不在本次召回文档内的引用会被整段降级为拒答 |
| `sources` | 本次实际召回的文档片段（含 `kb_id`，多库场景下据此区分来源库） |
| `steps` | 实际走过的图节点，用于证明「自适应」而非固定链式调用 |
| `trace` | 每个节点的耗时与备注，前端调试面板直接消费 |
| `route` | `vectorstore`（走知识库）/ 其他值表示闲聊或无需检索 |

**回答边界（三道闸）**：

1. **G1 无文档硬闸**——召回为空直接返回固定拒答话术，不调模型。
2. **G1' 拒答放行**——模型判定资料不足时，跳过引用校验，保留拒答原文。
3. **G2 引用白名单**——答案末尾的引用名必须命中本次召回文档，否则移除；全部伪造则整段降级为拒答。

### 3.2 `POST /chat/stream` — 流式问答（SSE）

请求体与 `/chat` 完全一致，鉴权一致，返回 `text/event-stream`。

**为什么需要它**：非流式的 P95 是 18–19 秒，用户全程盯着转圈。流式把「首字」拉到 5 秒内，
并把等待期拆成可见的阶段，体感差异远大于延迟数字本身。

事件类型（每帧 `data: {...}\n\n`）：

| type | 时机 | 载荷 | 前端该做什么 |
|---|---|---|---|
| `step` | 每个图节点结束 | `{node, ms, note?}` | 更新状态文案（见下表） |
| `token` | 生成过程中逐片 | `{text}` | 追加到当前气泡 |
| `reset` | 质检不过、要重新生成 | — | **清空已显示文本**，否则两轮答案会叠在一起 |
| `final` | 全部结束 | 同 `/chat` 响应体 + `session_id` | 用它的 `answer` 覆盖显示内容 |
| `error` | 异常 | `{detail}` | 显示错误并结束 |

阶段文案映射（前端内置）：`route` 正在理解问题 / `rewrite` 正在改写检索词 / `retrieve` 正在检索知识库 /
`grade_documents` 正在筛选相关段落 / `generate` 正在组织回答。

真实帧序列（线上实录，节选）：

```
data: {"type": "step", "node": "route", "ms": 782, "note": "vectorstore"}
data: {"type": "step", "node": "rewrite", "ms": 616, "note": "企业微信新增成员调用哪个API接口"}
data: {"type": "step", "node": "retrieve", "ms": 400, "note": "4 docs@kb['default']/hybrid"}
data: {"type": "step", "node": "grade_documents", "ms": 2513, "note": "1/4 relevant"}
data: {"type": "token", "text": "调用企业微信「创建成员」API接口，"}
...
data: {"type": "final", "answer": "...", "sources": [...], "session_id": "..."}
```

> ⚠️ **引用校验必须后置**：G2 要求看到完整答案才能判断引用真假，所以校验只能在生成结束后做。
> 极端情况下（答案里的引用全是伪造的），已推给前端的文字会被 `final` 整体替换为拒答话术。
> 前端必须以 `final.answer` 为准——这是刻意接受的取舍：宁可最后纠正一次，也不让用户干等 18 秒。
>
> 实测：`final.answer` 与已推 token 的差异通常只有引用行的空格规范化（353 字 vs 349 字）。

### 3.3 `POST /chat/reset` — 清空会话

| 项 | 说明 |
|---|---|
| 查询参数 | `session_id`（可选） |
| 响应 | `{ "ok": true }` |

## 5. 知识库

### 5.1 `GET /kbs` — 我可见的知识库

响应 200（真实返回）：

```json
[
  {
    "id": 1, "name": "产品通用知识库",
    "description": "内置语料：企业微信 / 腾讯会议 / 云服务器 / 对象存储 / 小程序",
    "created_by": "system", "created_at": 1793224536.7356348,
    "file_count": 0, "my_role": "super"
  },
  {
    "id": 2, "name": "产品部资料库", "description": "演示用",
    "created_by": "admin", "created_at": 1793224817.2426674,
    "file_count": 1, "my_role": "super"
  }
]
```

`file_count` 只统计**用户上传**的文件，不含内置语料（内置语料挂在 `default` 库的向量里）。

### 5.2 其余知识库接口

| 接口 | 权限 | 说明 | 主要错误 |
|---|---|---|---|
| `POST /admin/kbs` | admin | 建库，body `{ "name": "…", "description": "" }` | 400 重名 |
| `DELETE /admin/kbs/{kb_id}` | admin | 删库并清理其向量 | 404 库不存在 |
| `GET /kbs/{kb_id}/files` | 库成员 | 返回 `{ "my_role": "super", "files": [...] }` —— **是对象不是数组**。可见性（v3.1.2）：库管/super 看到全部（含他人待审批）；**其他成员看到「已入库的 + 自己上传的（含待审批/已驳回）」**，别人的未入库文件整条不返回 | 403/404 |
| `POST /kbs/{kb_id}/upload` | editor 及以上 | `multipart/form-data`，字段名 `file`；**≤20MB**（`workspace.MAX_FILE_MB`） | 400 格式不支持 / 抽取 0 字符 / 超过 20MB |
| `GET /kbs/{kb_id}/files/{fid}/download` | 库成员 | 下载原始文件 | 404 文件已丢失 |
| `GET /kbs/{kb_id}/members` | 库成员 | 成员与角色列表 | 403 |
| `POST /kbs/{kb_id}/members` | kb_admin 及以上 | body `{ "username": "…", "role": "viewer" }` | 403/404 |
| `DELETE /kbs/{kb_id}/members/{username}` | kb_admin 及以上 | 移除成员；不能移除库管理员 | 404 `成员不存在或为库管理员` |

> **两个上传接口限额不同**：内置语料 5MB、知识库上传 20MB。前端提示曾统一写 5MB，属保守提示，已按后端实际值更正。
>
> **上传即校验**：上传与审批前都会先跑一遍文本抽取，抽不到内容（扫描件未开 OCR、Excel 公式无缓存值等）**当场返回 400**，不会出现「文件在库里但一个字没进索引」的静默失败。

## 6. 文件审批

用户上传的文件默认 `pending`，需库管理员审批后才进索引。

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /files/{fid}/approve` | kb_admin 及以上 | 通过并触发建库 |
| `POST /files/{fid}/reject` | kb_admin 及以上 | 驳回，保留文件但不索引 |
| `DELETE /files/{fid}` | 上传者或库管理员 | 删除文件并重建索引 |

错误：`403 文件未通过审批`（试图下载未审批文件时）。

## 7. 管理接口

全部需要 `admin`/`superadmin`（除标注）。

### 7.1 用户管理

| 接口 | 说明 |
|---|---|
| `GET /admin/users` | 全部用户列表（含 `pending`） |
| `POST /admin/users/{username}/approve` | 审批通过，`pending → active` |
| `POST /admin/users/{username}/reject` | 驳回注册 |
| `POST /admin/users/{username}/disable` | 禁用 |
| `POST /admin/users/{username}/enable` | 启用 |
| `POST /admin/users/{username}/role?role=admin` | 改系统角色（**query 参数**，非 body） |
| `DELETE /admin/users/{username}` | 删除用户 |

### 7.2 内置语料

| 接口 | 说明 |
|---|---|
| `GET /admin/documents` | 列出内置语料文件 |
| `DELETE /admin/documents/{name}` | 删除内置语料（路径参数是文件名）→ `404 未找到该文档（内置语料不可删除）` 表示该文件来自上传而非内置 |
| `POST /admin/upload` | 上传到内置语料区（`multipart/form-data`，字段 `file`）；**≤5MB**（`documents.MAX_UPLOAD_MB`） |

### 7.3 索引运维

**`GET /admin/index-status`** —— 最常被调用的运维接口：

```json
{
  "building": false,
  "chunks": 185,
  "built_at": "2026-10-30 07:19:10",
  "error": null,
  "progress": {
    "phase": "done", "pct": 100, "docs": 39, "total": 39,
    "chunks": 185, "total_chunks": 185, "started_at": "07:19:07", "elapsed": 2.7
  },
  "skipped": [],
  "by_format": { ".md": 38 },
  "keyword_index": {
    "mode": "ready", "chunks": 185, "kbs": 2,
    "revision": 0, "built_revision": 0, "building": false,
    "built_at": "2026-10-30 07:58:20", "build_seconds": 0.34,
    "max_chunks": 20000, "error": null
  }
}
```

| 字段 | 含义 |
|---|---|
| `progress` | 重建进度，重建中可轮询（`pct` / `docs` / `elapsed`） |
| `skipped` | 被跳过的文件及原因（不支持的格式、抽取为空等）——**这里是排查「文档没进库」的第一现场** |
| `by_format` | 按扩展名统计的入库篇数 |
| `keyword_index.mode` | `ready` / `building` / `disabled`（超 `max_chunks` 降级为纯向量）/ `error` |
| `keyword_index.revision` vs `built_revision` | 两者不等表示关键词索引落后于向量库，正在后台重建 |

**`POST /admin/rebuild`** —— 全量重建向量库 + 关键词索引。响应 `{ "ok": true }`，随后用 `index-status` 轮询。

**`GET /admin/search?q=存储桶`** —— **仅 superadmin**。绕过问答链路直接看检索结果，用于排障：

```json
{
  "results": [
    {
      "kb": "产品通用知识库",
      "source": "对象存储 创建存储桶_腾讯云_d457c4134b.md",
      "preview": "。 4. 在跳转的 创建存储桶 界面中，配置如下信息：..."
    }
  ]
}
```

> 注意外层是 `{"results": [...]}`，不是裸数组。

**`GET /admin/audit`** —— 审计日志，查询参数 `limit` / `action` / `username`。

## 8. 端到端联调（可直接粘）

```bash
BASE=http://<host>:8080/api

# 1) 登录，取 token（字段名是 token）
TOKEN=$(curl -s -X POST $BASE/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"********"}' | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 2) 探活
curl -s $BASE/health

# 3) 看我可见的库
curl -s $BASE/kbs -H "Authorization: Bearer $TOKEN"

# 4) 问答
curl -s -X POST $BASE/chat \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"腾讯会议可以设置几个联席主持人？"}' | python -m json.tool

# 5) 看索引状态
curl -s $BASE/admin/index-status -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 6) 上传一个文件到 2 号库
curl -s -X POST $BASE/kbs/2/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@./腾讯会议版本配额表.xlsx"

# 7) 重建索引并轮询
curl -s -X POST $BASE/admin/rebuild -H "Authorization: Bearer $TOKEN"
curl -s $BASE/admin/index-status -H "Authorization: Bearer $TOKEN"
```

预期结果：第 4 步应返回拒答（库里没有「联席主持人」这个角色，只有「指定主持人」），且 `sources` 中不含配额表；
若在第 6 步上传了配额表并完成重建，再问「企业版的联席主持人上限」，应回答「50 位」并引用该表。

## 9. 变更与兼容

| 版本 | 接口层变更 |
|---|---|
| v2.1 | 引入 JWT；管理接口从 `X-Admin-Token` 切换为 `Authorization: Bearer`（旧头已失效） |
| v2.2 | 新增多知识库、成员、文件审批、审计 |
| v2.3 | 上传支持 pdf/docx；新增 `index-status` 的 `progress` / `skipped` / `by_format` |
| v2.4 | 上传支持 xlsx/pptx；`index-status` 增加 `keyword_index`（关键词索引状态与版本号） |
| v2.5 | **新增 `POST /chat/stream`（SSE 流式）**；`/chat` 保留不变，两者共用同一张图与同一返回结构 |

**兼容性约定**：`answer` / `sources` / `steps` / `trace` / `route` 五个字段自 v2.0 起未变，接入方只依赖这五项即可长期稳定。
流式接口是**新增**而非替换，老接入方继续用 `/chat` 不受影响。

## 10. 开放管理 API（v2.6 新增）

供外部程序调用：机器人、运维脚本、其他模型/Agent。**鉴权方式与业务接口不同**：
请求头 `X-API-Key: <ADMIN_API_KEY>`（服务端 `.env` 的 `ADMIN_API_KEY`，未配置则整个通道返回 403 关闭）。
操作全部写入审计日志（操作人记为 `openapi`）。以下 `$BASE = http://<host>:8080/api`。

### 10.1 用户列表

```
GET $BASE/open/v1/users?group=技术支持一部&status=active

### 10.2 分组统计

```
GET $BASE/open/v1/groups
→ {"groups": [{"group": "技术支持一部", "total": 1, "active": 1}, {"group": "", "total": 1, "active": 1}]}

### 10.3 创建用户

```
POST $BASE/open/v1/users
{"username": "zhangsan", "password": "Init@2026x", "display_name": "张三",
 "group": "技术支持一部", "auto_approve": true}
→ 用户对象（auto_approve=true 时创建即激活，免网页审批）
```

### 10.4 批量操作（分组成员/批量权限的核心）

```
POST $BASE/open/v1/users/batch
{"usernames": ["a", "b", "c"], "action": "set_group", "value": "技术支持一部"}
→ {"action": "set_group", "total": 3, "succeeded": 3,
   "results": [{"username": "a", "ok": true}, ...]}
```

`action` 取值：`approve` / `disable` / `enable` / `set_role`（value=user|admin）/ `set_group`（value=分组名）/ `delete`。
逐个执行互不中断，单个失败不影响其余，结果逐条返回。

### 10.5 无会话问答（外接模型入口）

```
POST $BASE/open/v1/chat
{"question": "企业微信如何获取access_token？", "kb_ids": null}
→ {"answer": "...", "sources": [...], "route": "rag|chitchat|refuse"}
```

不占用户会话、无多轮历史；`kb_ids` 传 `null` 走默认库。适合让外部 Bot / 其他模型把本系统当「带引用的知识工具」调用。

## 12. 分组授权 API（v2.7 新增）

知识库可授权给**整个分组**（部门/团队），该组成员（含未来新增）自动获得访问权。
检索范围 = 默认库 + 个人成员授权的库 + 所在分组被授权的库。个人授权优先于分组授权。
以下 `$BASE = http://<host>:8080/api`，JWT 鉴权，需 kb_admin/super 权限。

```
GET    $BASE/kbs/{kb_id}/groups          → [{"grp":"财务组","role":"viewer","granted_by":"admin",...}]
POST   $BASE/kbs/{kb_id}/groups          {"group":"财务组","role":"viewer"} → 授权/更新
DELETE $BASE/kbs/{kb_id}/groups/{group}  → {"ok":true} 收回
```

数据模型：`kb_groups(kb_id, grp, role, granted_by, granted_at)`；审计动作 `group.grant` / `group.revoke`。

## 14. 知识库治理接口（v3.1 新增）

库数量上来后，「名称 + 描述」不足以治理：找不到归谁管、什么密级、还用不用。
本版给 `kbs` 补了标准元信息，并新增治理专用接口。以下 `$BASE = http://<host>:8080/api`。

### 14.1 知识库对象新增字段

```
code        TEXT     知识库编码，KB-0007 形式；创建时可按 KB-<部门>-<序号> 自定义
dept        TEXT     归属部门
level       TEXT     public | internal | confidential（数据分级）
owner       TEXT     负责人用户名
status      TEXT     active | archived（归档库不参与检索）
updated_at  REAL     元信息或文件变动时间
```

列表额外返回统计列：`file_count / pending_count / member_count / group_count / my_role`。

### 14.2 列表（带治理筛选）

```
GET $BASE/kbs?q=财务&dept=财务部&level=confidential&status=active
→ [{...kb, "my_role": "kb_admin"}]
```
`q` 匹配名称/编码/描述；部门与分级为精确匹配；越权库不出现（按 `readable_kb_ids` 过滤）。

### 14.3 新建 / 更新 / 删除

```
POST   $BASE/admin/kbs  {"name":"...","description":"...","dept":"财务部",
                         "level":"confidential","owner":"caiwu1","code":"KB-FIN-001"}
PATCH  $BASE/admin/kbs/{id}  {任意子集: name/description/dept/level/owner/status}
DELETE $BASE/admin/kbs/{id}  → 级联隐藏文件（默认库不可删除、不可归档）
```
`PATCH status=archived` 是软下架：文件与审计保留，但 `readable_kb_ids` 不再返回该库，问答无法命中。

### 14.4 权限矩阵

```
GET $BASE/admin/kb-matrix
→ {"groups":[{"group":"财务组","total":1,"active":1}],
   "rows":[{"kb_id":7,"name":"财务账单库","code":"KB-0007","dept":"财务部",
            "level":"confidential","status":"active","grants":{"财务组":"viewer"}}]}
```
一次取全「库 × 分组」授权关系，避免按库循环。授权改用 `POST /kbs/{id}/groups`、收回用 `DELETE /kbs/{id}/groups/{group}`。

### 14.5 成员候选人（库管理员可用）

```
GET $BASE/kbs/{id}/candidate-users
→ {"users":[{"username":"zhang1","display_name":"一部·小张","group":"技术支持一部"}]}
```
返回**尚未直接授权**的激活用户。有这个接口后，库管理员加成员不再需要系统管理员权限的用户列表。

### 14.6 行为变更（破坏性，需注意）

| 变更 | 说明 |
|---|---|
| 分组授权校验存在性 | `POST /kbs/{id}/groups` 传不存在的分组返回 **400**（此前会写入孤儿授权，且矩阵看不见） |
| `updated_at` 语义扩展 | 上传、审批通过/拒绝、删除文件都会更新它——列表「变更时间」才可信 |
| 归档库退出检索 | `readable_kb_ids` 只取 `status='active'`，归档即下架问答 |
