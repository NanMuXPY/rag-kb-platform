# 云服务器 SSH 连接与安全组排查

## 问题一：连续输错用户名触发防暴力破解封禁

**现象**：SSH 反复连接失败几十秒后，连密码正确的账号也连不上了，本机所有请求被服务器拒绝。

**原因**：云厂商和 fail2ban 这类工具对**短时间高频失败登录**有自动封禁策略，连续试错用户名/密码会触发封 IP，通常持续 15 分钟左右。

**解决与预防**：

- 被封后等待解封，期间不要继续重试（会刷新封禁计时）；
- 连接前先确认用户名（root 还是实例自定义用户名），只用确认过的凭据连接；
- 固定出口 IP 场景，把本机出口 IP 写入 `/etc/fail2ban/jail.local` 的 `ignoreip` 白名单；
- SSH 统一用密钥文件（pem）登录，权限设为 600。

## 问题二：服务已启动但公网访问不通

**现象**：服务在服务器上监听正常，`curl 127.0.0.1` 通，但外网访问超时。

**排查顺序**：

1. 服务器防火墙（firewalld/iptables）是否放行端口；
2. **云控制台安全组**是否放行了该端口的入方向规则——这是最容易漏的一步，服务器内部完全看不到安全组的存在；
3. 服务是否监听 `0.0.0.0` 而不是仅 `127.0.0.1`；
4. 中间层（如 nginx 反代）的 upstream 端口是否与后端实际端口一致。

## 通用建议

- 生产端口规划：公网只暴露一个入口端口（如 8080），后端服务端口只在容器内网暴露（expose 不映射宿主机）；
- 敏感信息（API Key、管理口令）放服务器上权限 600 的 `.env`，不进代码仓库、不进部署压缩包。
