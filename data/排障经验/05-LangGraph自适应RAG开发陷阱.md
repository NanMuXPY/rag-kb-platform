# LangGraph 自适应 RAG 开发常见陷阱

## 陷阱一：条件入口边不能更新状态

**现象**：想在图的入口处先做一次路由判断并把结果（如意图标签）写进 state，把路由函数直接挂到 `set_conditional_entry_point`，结果路由返回的字典没有进入 state，下游节点拿不到。

**原因**：条件入口只能返回"去哪个节点"的字符串，**不具备 reducer 语义，返回的状态更新会被丢弃**。

**解决**：显式加一个 `start` 节点，负责路由判断并把结果写入 state，再用普通条件边从 `start` 出发分发。

## 陷阱二：重试环无法逃逸

**现象**：质检不通过→改写→重新生成的环转个不停，进程不报错但永不结束。

**原因**：重试计数放在了函数局部变量或全局变量里，图的重入没有正确累积；多个会话并发时还会互相污染。

**解决**：把重试计数器放进 **GraphState**（如 `retry_count`），由触发重试的节点显式 `+1`，条件边读取计数器超过阈值即跳出环走降级路径。状态内计数天然随会话隔离，也解决了并发安全。

## 陷阱三：改写链输出类型不对

**现象**：问题改写节点的下游拿到的不是字符串而是带角色包装的消息对象，拼接 prompt 时报类型错误。

**原因**：改写链最后一级没有接 `StrOutputParser()`，LLM 返回的 AIMessage 直接透传了。

**解决**：任何"链的产物要当纯文本用"的环节，末尾都补 `| StrOutputParser()`。

## 陷阱四：拒答被质检判死循环

**现象**：检索为空时按设计返回标准拒答话术，但质检节点把"没有引用资料的回答"判为 not useful，又送回改写重试，形成拒答→回炉→再拒答的循环。

**解决**：两道闸配合——①生成节点入口发现 documents 为空，直接返回拒答，不调 LLM；②质检节点识别"已经是拒答话术"时直接判 useful，放行。实测该方案把拒答准确率从 80% 提到 100%，端到端 P95 延迟从 58 秒降到 25 秒。
