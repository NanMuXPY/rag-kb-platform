# 大模型 API 批量限制与限流处理

## 问题一：批量向量化报 400

**现象**：调用 embedding 接口批量向量化文档，单次请求超过 10 条时报 `400 batch size is invalid`。

**原因**：部分服务商对单请求 embedding 条数有硬上限。以阿里百炼 text-embedding-v4 为例，单请求上限 **10 条**，客户端框架（如 LangChain）默认 chunk_size=64 会直接触发 400。

**解决**：把客户端的 batch 参数与服务商上限对齐（LangChain 中是 OpenAIEmbeddings 的 `chunk_size=10`）。联调新服务商时，先用最小请求探测批量上限，再写进配置，不要照搬框架默认值。

## 问题二：小参数模型持续 429

**现象**：换更便宜的小模型（如 qwen-turbo）后，请求持续返回 429 限流。

**解决**：

- 该 Key 下小模型配额不足以支撑并发，改用配额充足的主力模型；
- 确需用小模型时，批量实验走**串行 + 指数退避**（失败后等待 1s、2s、4s… 重试），而不是并行压测。

## 通用建议

- 对话与向量化可以用同一个 OpenAI 兼容 Key（同一 base_url 下两个模型），减少多 Key 管理成本；
- 结构化输出（JSON）在不同服务商支持程度不同：优先 function_calling，复杂提示词易失败的服务商改用 json_schema，把选择做成可配置项而不是写死。
